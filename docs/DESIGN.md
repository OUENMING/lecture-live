# ClassLive · 本地实时课堂双语字幕

把英文课实时变成「**英文草稿 → 句末定稿 → 中文流式打字机**」,全本地、离线、$0。
复刻商业产品「说完一句按上下文自动修正」的效果,并支持课后自动归档到 Obsidian。

## 效果

```
草稿(Parakeet 实时):  ▸ I'm contacting you in relation to Eco.
句末定稿 + 流式中文:   🌐 我是在就 Econ 10101 与你联系。   ← 中文先出(~0.6s)
                       EN: I'm contacting you in relation to Econ 10101.
```

## 架构

```
音源(麦克风 / BlackHole 系统声 / 文件)  ← 回调式异步采集(不阻塞主线程)
  → PeakNormalizer: 滑动峰值归一化(补远场衰减, 不削顶)
  → Silero VAD(深度学习)判语音 + 梯级静音切句 + 300ms pre-roll
       dur<3s→0.6s静音 | 3–7s→0.3s | >7s→0.25s | 上限12s
  → Parakeet-TDT-0.6B-v3 int8(sherpa-onnx, CPU, ~28× 实时)
       说话中每 1s 刷草稿 / 句末整句重转定稿
  → 标点断句 → 逐句流式: Qwen3-1.7B-4bit(mlx-lm, GPU)
       RAG-lite 术语筛选(核心词常驻 + 动态召回 Top-3 + 课程术语全量 + 领域声明)
       输出 ZH: ... / EN: ...  → 中文逐字打字机 → 英文随后
  → 卡片式悬浮窗(中英垂直贴合) / 终端
  → ObsidianWriter 逐句落盘 → 课后二次精修(领域+术语整批重矫正/重译) → 双层笔记
```

## 实测性能(M1 Pro 16GB)

| 指标 | 值 |
|---|---|
| ASR | Parakeet 12s 音频 0.43s(≈28× 实时) |
| 首字中文 | **0.60s**(RAG-lite 后,原 0.82s) |
| 句末→中文完成 | ~1.0s |
| 内存峰值 | ~1.3GB |
| 磁盘 | 模型 ~2GB |

> ⚠️ **本机模型上限**:OOM 由「模型大小 × prompt 长度」共同触发。
> - Qwen3-4B / Qwen3.5-4B → **必 OOM**
> - Qwen2.5-3B → RAG-lite 缩小 prompt 后**可跑,但格式遵循差**(常不按 ZH/EN 格式输出)、慢一倍
> - **Qwen3-1.7B → 默认**(最快、格式稳)
> 已试 `set_cache_limit`/`set_memory_limit`/`max_kv_size` 均无法突破 4B。

## 悬浮窗 UI

卡片式双语流动排版,每卡中文(18pt Medium,最多两行)+英文(11pt Medium)垂直贴合。
**阅读流向:上方旧、下方新;最底部是 💡 术语行**(钉底,不随句子滚,点击可展开解析)。

> 排版细节(为什么这么定):中文两行实测 42.0px,框留 47px。**两行覆盖 100% 观测数据**
> (151 句真实定稿 p90=34 字、max=56 字,超过两行 66 字的 0 句)。
> ⚠️ AppKit 的 `NSLineBreakByTruncatingTail` **强制单行、不换行** —— 想要多行必须
> `WordWrapping` + `maximumNumberOfLines_(N)`。旧代码用 `maxLines=1` 导致 11% 的长句
> **第二行被静默吃掉、连省略号都没有**,现在已修。

### 收起 / 展开

| 模式 | 高度 | 显示 | 滚动 |
|---|---|---|---|
| **收起**(默认) | 330px 固定 | 3 句(2 历史 + 1 当前)+ 💡 一行 | ❌ 不可滚(滚轮被吞) |
| **展开** | **屏可见高的 60%** | 任意多历史 + 💡 最多三行 | ✅ 可自由翻 |

- 展开态**顶边不动**(面板向上长高),顶栏按钮不跳。
- 展开态**实时行钉在底部**,只有历史可滚 —— 和聊天软件一致。
- **闲置自动回底**:翻到上面看历史时,若又有**新句定稿**,静置 6s 自动回底;
  若只是翻着没新内容,**不会**把人拽下去。
- 滚动中追加新句时**视野不漂**(视口随内容同步上移)。
- 定稿瞬间**不会重复一行**:历史与实时行必须**原子**写入同一次绘制 —— 固定行高下实时行的
  显隐不改变布局,分两次写会让最新句同时出现在历史末尾和实时位(屏上多一行)。

> 顶栏按钮**右对齐 + 按文字实测宽度自适应**(`sizeToFit` + 内边距,图标保底 28px 点击区)。
> 旧代码硬编码 x 坐标,「展开」占 `[W-170,W-108]` 而「译 开」占 `[W-130,W-74]`,**交叉 22px**
> → 渲染成糊在一起的「展开译 开」。现在中英切换、展开/收回换字都不会再重叠。

| 按钮 | 位置 | 作用 |
|---|---|---|
| ▾ 展开 / ▴ 收回 | 面板右上 | 切换收起/展开 |
| ↓ 最新 | 面板右上(翻上去后才出现) | 回到最新一句 |
| 🌐 译 开/关 | 面板右上 | **翻译开关**,随时点随时切(见下) |
| ⭐ | 面板右上 | 标记**当前句**为重点(Obsidian 里加 `⭐ Exam Focus`) |
| ✕ | 面板右上 | 退出(走优雅关闭: 冲刷队列 + 落盘总结) |
| 🎧 | **菜单栏** | 菜单: 开启/关闭**鼠标穿透**、退出 |

### 白底可读性

毛玻璃(`NSVisualEffectView` / `HUDWindow`)在**纯白 PPT** 前会把白压成浅灰:
实测白底透过材质后亮度仍有 **0.363**,白字对它只有 **2.54:1**(AA 需 4.5:1)。
想纯靠填充色达标需要 alpha≈0.85 的黑底 —— 那等于放弃毛玻璃。

所以采用**字幕界通行做法**:材质之上压一层 `SCRIM_ALPHA=0.45` 的半透明黑,
文字再加**紧凑黑描边**(blur 1.5 / α0.80)。**可读性由描边承担**,底色只需压暗到
让描边有依托。纯填充对比度在任意背景(彩图/白 PPT)上都救不了字,轮廓可以。

### 🌐 翻译开关(随时切换)

点一下就在「双语」和「只英文」之间切,不用重启。按钮文字直接写状态(`译 开` / `译 关`),
**不靠图标变暗**——emoji 不吃 tint 且弱显色看不清。

- **关闭时**:只停**中文**——不产译文、不查术语解析(解析本身是中文)。
  **英文仍走同一个模型做上下文矫正**,ASR 错听照修,阅读流向不变。
  落盘写 `**EN**: <矫正后>` + `**ASR**: <原始>` 两行。
- **随时可逆**:重新打开即刻恢复双语,上下文(`finals`)一直连着,不会断链。
- 中途切换是安全的:开关只在下一次定稿/草稿时生效,在途结果不会错乱。
- ⚠️ **矫正失败一律回退原始 ASR**(不显示空行、不丢转录),与翻译路径同规矩。

> 「不翻译」≠「不联网」。关掉中文后**仍会调模型做英文矫正**——这是刻意的:
> 关掉它的理由是"不要中文",不是"不要修正"。真要做到零模型/零网络,
> 用 `--engine local` 断网跑(或直接不配 key),失败时会自动退成纯 ASR 转录。

英文矫正的结果会被**三重把关**(`_clean_fix`),不满足就回退原始 ASR:
① 混入中文 → 说明模型跑偏去翻译了;② 空;③ **明显变长** → 说明它在改写而不是矫正
(这个功能的承诺就是"本来就对的词原样保留")。实测:"nation to"→"relation to"、
"publicate"→"plagiarize"、"essential means"→"essential readings" 都修对了,
而本来就正确的句子**一个词都没动**。

> ⚠️ 终端 UI(`--ui terminal`)没有按钮,开关只在悬浮窗可用。

> **鼠标穿透为什么不在面板上**:开启后窗口忽略**所有**鼠标事件,面板按钮会集体失效(单向死锁)。
> 所以穿透只从菜单栏 🎧 切换——菜单栏永远可点。
> 按钮目标对象保存在 `Overlay._targets` 里(NSControl.setTarget_ 是**弱引用**,不持有会被 Python GC 回收 → 点击静默失效);
> `pump()` 还必须显式排空 NSApplication 事件队列并 `sendEvent_`,否则鼠标点击永远到不了窗口。

> **滚动流畅度的两个坑**(改 `pump()` 前务必知):
> ① **手势期间让步要几乎为零**,否则两批滚轮事件之间那轮会睡满 8ms,事件在队列里干等 → 视口更新被量化成 8ms 桶,与 120Hz 手势拍频 = 肉眼卡顿。
> ② **但让步不能真的跳过** —— 不跑 run loop 时 CoreAnimation 不提交,**画面会整个冻住**(实测滚到别处截图全空白)。
> 正解 `runUntilDate_(NSDate.distantPast())`: 立刻返回但**仍跑完一轮** run loop,实测 0.003ms。

终端里 **Ctrl+C** 同样优雅退出。

## 术语表(分课程)

```
glossary.txt          ← 公共: 课号、考核相关(所有课通用) — 由 glossary.example.txt 复制
glossary/             ← 分课程(每行一个术语, 文件名 = 课号; 自备, 不入库)
```

- **课号必须全列在公共表里**:同一院系的课号往往发音极近(如 `…-70 / …-30 / …-40 / …-90`
  只差一个词),不给候选必然听混。
- **当前课号常驻注入**(`core_terms(course)`),其余按句子动态召回 Top-3(注入 ~40 token)。
- **术语表是最大的质量杠杆,远大于 prompt 措辞**。实测:ASR 听成 "essential means" 时,
  无术语表 → 翻成「小测验」(崩);有术语表 → 「小测验也是基于必读材料的」+ 英文行也纠正。
- 加词方式:直接往对应 `glossary/<课号>.txt` 加行即可(上课听到新术语就补)。
- **课号可用短代号**:`cl course 10202` 会存进 `.course`,载入时按**后缀**匹配到
  `glossary/ECON10202.txt`。严格拼 `glossary/10202.txt` 会**静默落空** ——
  实测只加载到 38 条公共术语、79 条课程术语一条没进(已修)。
- **别放单字母词**(如把 R 语言写成 `R`):`select_terms` 的"整句包含"判断会让
  `"r" in sentence` 几乎**每句都真**,于是每句都把它注入到翻译 prompt(已删)。

```bash
cl course             # 列出可选课程(带 * 标当前)
cl course ECON10101   # 切换课程
```

## 两级矫正(实时 + 课后)

实时字幕求快,落笔记求准,矫正分两级:

- **一级(实时,`translator.py` / `cloud_translator.py`)**:每句单次调用。prompt 里放
  ①领域声明(`domain_block`,由课程术语表首行提取)②**课程术语全量注入**(`always=`,
  不再只召回 Top-3)③few-shot 听错样例(`max chocolate`→`macroscopic` 等)④防过度矫正规则
  (已正确的词原样保留)。**中文必须译"矫正后的读法",绝不直译原始噪声**。
- **二级(课后,`polish.py` + `--polish`)**:落笔前把整节课按 30 句一批重做,带
  领域 + 全课术语 + 前几行已精修上下文。**关键**:输入同时给"直播已矫正的 EN"与"原始 ASR",
  以 **EN 为基准** —— 只喂 ASR 会让模型对着原始噪声重新判断,把直播已改对的词又抄回错的
  (实测 `lattice`→`lacker`、`statistics`→`stalcy`、`binding`→`burn`)。判断标准是
  "在本课语境里讲不讲得通",不是"是不是真实英文单词"(听错常落在真实单词上,如 `chocolate`)。
  实测一堂 482 句热力学课:修正 16 句(`delta T`→`delta U`、`end of combustion`→`enthalpy of
  combustion`、`letter Jones`→`Lennard-Jones`、`torque figures`→`torsion angles`…),0 句倒退。
- 会话文件里实时落盘的 **ASR 原文与直播译文保持不动** —— 原始 ASR 是复核凭据,精修版只是
  "更好读的那一版"。精修批次失败原样保留,绝不因 API 问题丢内容。

## 记录落盘(先落盘,再询问 —— 永不丢)

```
运行中: sessions/<日期>_<时间>_<课程>.md   ← 每句定稿立刻追加写入
   ↓ 结束时询问
答「是」 → 复制到 <vault>/Lectures/<日期>_<课程>.md(Obsidian 正式笔记)
答「否」 → 会话文件保留, 并告诉你路径(不会丢)
```

**为什么这样设计**:曾经出现过一次事故 —— 45 分钟、544 句的课堂记录,在"是否保存"提示处误按 **Ctrl+C**,旧版本把它当成"不要保存"直接丢弃,且当时用的是悬浮窗模式,终端里没有任何副本,**内容永久丢失**。

现在的保证:
- **实时落盘**:每句定稿立即写文件,`kill -9` 强杀 / 断电 / 崩溃都只损失最后一句;✕ / Ctrl+C 会先冲刷分段器残余语音再退出(在途半句不丢,收尾等待有界 15s);
- **Ctrl+C 与 EOF 一律默认保存**(绝不再因一次误按丢整节课);
- **答"否"也不会丢**:会话文件仍在,用 `cl last` 可查看。

```bash
cl last          # 查看最近一次课堂记录(含句数与前几行)
```

`--save-notes no` 才会完全不建文件。

### 存入 Obsidian 的笔记是「双层」的

```
<vault>/Lectures/<日期>_<课程>.md
├── 复习层(自动生成, 一分钟看完)
│   ├── 🎯 一句话概览          ← LLM 生成, 只依据本课转录, 不得引入外部知识
│   ├── ❓ 复习自测(3–6 条)   ← `问题::答案`, 可被 Spaced Repetition 插件识别
│   ├── 💡 本课术语表          ← 带首次出现时间戳, 本地查表(零网络)
│   └── ⭐ 我标记的重点        ← 课上按过 ⭐ 的句子(原文 + EN)
└── 📜 完整逐句转录(默认折叠)  ← **逐字保留**: EN / ZH / 原始 ASR, 一句不删
```

**双层 ≠ 摘要**。复习层只是**入口**;下面那份转录是**逐字保留、未做任何删改**的完整记录 ——
"不遗漏任何要点"靠的是它,因为摘要必然把细节吃掉。原始会话文件(`sessions/`)也一直存在,
格式更朴素,是崩溃时的兜底副本。

复习层里的 🎯/❓ 走一次 LLM 调用(有 key 才生成,失败/没网则降级为可手填的空槽),
💡/⭐ 纯本地推导、零网络。**转录永远完整落盘** —— 复习层生成失败不影响任何内容。

## 数据落盘一览(回答"录音和文字会保存吗")

| 数据 | 是否保存 | 说明 |
|---|---|---|
| **音频** | ❌ **从不** | 只读音频流做转写,不写任何音频文件;要留录音请自己另外录 |
| **原始 ASR 转录** | ✅ **总是** | 每句记 `**ASR**:` 行(未修正)。LLM 偶尔过度修正,原始版是复核凭据 |
| 双语文字(会话文件) | ✅ **总是** | `sessions/` 实时写入,防丢底稿 |
| 双语文字(Obsidian) | ⚠️ 询问后 | 答"是"才复制进库;**不设 `--course` 也会写**(课名默认 `LECTURE`) |
| 草稿译文 / 💡 术语行 | ❌ | 只在屏幕上显示(点开的解析也不落盘) |
| `term_notes.json` | ✅ | 术语解释**策展库**(三档,非课堂内容) |
| `term_notes_auto.json` | ✅ | 专有名词**自动缓存**(可整文件删,非课堂内容) |
| `.course` / `.deepseek_key` | ✅ | 配置,非课堂内容 |

每句记录的字段:

```markdown
> [!abstract] 22:01:44
> **EN**: ... to Brightspace today is our main source ...   ← LLM 修正版
> **ZH**: 我们可以访问，嗯，Brightspace，今天它是我们获取...   ← 中文译文
> **ASR**: ... to bright space today is our main source ...  ← 原始转录(对照用)
```

翻译失败时不会连转录一起丢:该句只写 `**ASR**` 行,内容仍在。

## 术语自动解析(💡)

字幕里出现**真·难词或专有名词**时,面板最底部出现一行术语提示 —— **查表,零额外延迟**。
**默认只列术语名**(便宜、不抢阅读);**点一下**那一行才展开完整解析,并把这条**钉住**:

```
◈ Catholic Church · polycrisis  ▸ 点开解析      ← 默认: 只有名字, 可点
📌 Catholic Church：天主教教会是基督教中规模最大的宗派，以罗马教宗为最高领袖……
```

**为什么是"点击触发"**:字幕每 1s 换一句,而解析读完要好几秒 —— 自动弹解析会跟你抢眼睛。
调研发现所有商用产品(Teams/Otter/Wordly/Apple Live Captions)都**不向观众显示释义**,
只有教育类工具(RTGX/Subify)做这件事,而它们一律用**点击/悬停触发 + 可钉住**;
Subify 那种 2 秒自动消失的 tooltip 被公认为反面案例。

**两条持久性规则**(这是"太快消失"的真因 —— 旧代码在 `finalize()` 里清空术语槽,
于是术语名只活 1 句):
- `_terms`(本句命中的术语名)**不随 `finalize()` 清空** —— 下一个命中才会换;
- `_pinned_term`(点开的解析)**不会被新术语顶掉**,直到再点一次取消。

**显示**:收起态一行(尾部省略),展开态最多三行 —— 同一份字符串,只靠 frame 高度与换行模式切换。
点开后 `📌 名字：` 前缀占掉约 2.5 行宽,所以展开态放得下完整 80–160 字解析(实测)。

### 三档筛选(关键)

术语不是"命中就解释"。每条在**构建时**被模型分到三档,判断标准是**中英对照价值**
(不是"概念难不难" —— 本应用是英译中,要给的正是英文词→中文术语的即时对照):

| 档 | 含义 | 命中后显示 | 例子 |
|---|---|---|---|
| `gloss` | 学生知识之外、真需要展开的难点 | **完整解析**(80–160 字) | `endogeneity`、`constrained optimization`、`Byzantine Empire` |
| `basic` | 本课程基础概念,但英文↔中文要即时对上 | **一行速查**(≤30 字) | `demand`、`marginal cost`、`standard deviation` |
| `skip` | 后勤词 / 课号 / 自明词 | **永不显示** | `deadline`、`module`、`ECON10202` |

**`gloss` 与 `basic` 都参与运行时匹配** —— `basic` 曾因"学生看名字就懂"被排除,
但那等于砍掉一半该显示的词:依赖变量 / 哑变量 / 直方图…**"看中文名字就懂"≠"看英文词就懂"**。
保留 `skip` 条目是为了**幂等**(重跑不重复问模型)且**可审计** ——
想让某个词出现,把 `level` 改成 `"basic"` / `"gloss"` 再 `--rebuild` 即可。

### 匹配用词边界,不用子串

```python
r"\b" + term + r"(?:s|'s)?\b"     # 允许复数, 不允许子串
```

旧实现是 `if tl in low:` —— `GG` 命中 *su**gg**est / stru**gg**le / bi**gg**er*,
`Four` 命中 *fourth*,`Econ` 命中 *economic*。现在 `\bgg\b` 只匹配独立的 GG。

### 两条来源 + 信任分层

1. **术语表** → 构建时预生成**分层**解释(`python build_notes.py`),运行时纯查表。
2. **专有名词**(人名/机构/地名,如 `Wolfe Tone`、`Constantinople`)→ 后台异步查,
   结果进 **`term_notes_auto.json`**(与策展的 `term_notes.json` **分文件**)。

> **为什么要分文件**:自动查询的结果**永久缓存**,旧实现曾把 51 条垃圾(含幻觉,如
> `Ender Hargadin`→「一个虚构的奇幻角色名字」)写进策展文件、悄悄淤积。
> 现在垃圾**可审计、可一条命令清空**:`rm term_notes_auto.json`。

自动查询的**入口闸门**(挡住幻觉与 ASR 乱码):

- **第 2 次出现才查**(`seen_proper` 是 `Counter` 不是 `set`)—— 一次性误听进不来;
- `lookup_term` 必须返回 `{"known": true, "type": "person|org|place|concept"}`,
  否则**不缓存、不显示**;
- `detect_proper_nouns` 有**普通词汇否决**(高频词 / 单音节 / 句首单个大写词)。

```bash
python build_notes.py            # 增量: 只为新术语生成解释
python build_notes.py SOC10101   # 只为某门课
python build_notes.py --rebuild  # 全量重分类 + 扩写 + 清掉自动回写的垃圾
```

> **实测效果**:151 句真实课堂转录上,旧版**每 2 句触发一次**(76 次,多为
> Yeah/Don't/Four/module/课号);修好词边界 + 入口闸门后降到 **12 次**(仅 `gloss` 档);
> 把 `basic` 档纳入匹配后为 **20 次(每 7.5 句)**,命中**全部是真术语**
> (demand ×7、Catholic Church ×3、Roman Empire ×3、Byzantine Empire ×2、
> constrained optimization、endogeneity …),常见词("function/mean/structure")没有刷屏。
>
> 成本:全量生成约 4 次请求(~0.01 元);`basic` 一行速查另约 11 次请求;
> 运行时只有"新专有名词"会联网,其余为零延迟查表。

## 收音灵敏度(远场为什么能收到)

**瓶颈不是信噪比,是绝对电平。** 实测:把一段真实课堂录音**等比衰减**(信号和噪声一起降,
信噪比完全不变),词数从 73 掉到 6 —— 说明 Silero VAD 和 Parakeet 都吃"响度",
讲师在讲台比凑近说低 20–30dB,于是就"识别不到"了。

修法是进 VAD/ASR 之前先补电平(`capture.PeakNormalizer`):

- **滑动峰值**而非逐块峰值。逐块自适应会跟着音节抖动,增益抖动本身就把句子切碎
  (VAD 判定随增益起伏);滑动峰值让增益在**句内近似恒定**,只跨句缓慢适应。
- **峰值保护**:增益受 `0.95/当前块峰值` 钳制,先放大再削顶的事不会发生。
- **上限 30dB**,避免把纯底噪也放大到让 ASR 编词。

效果(同一段录音逐级衰减,端到端走真实 `load_source` 路径):

| 输入电平 | 修复前 | 修复后 |
|---|---|---|
| -30 dBFS(正常) | 73 词 | 71 词 |
| **-42 dBFS** | **35 词** | **74 词** |
| -54 dBFS | 12 词 | 69 词 |
| -66 dBFS | 5 词 | 56 词 |
| -72 dBFS | 1 词 | 39 词 |

可用动态范围扩大约 **24dB**(≈ 自由场 4.6 倍距离)。安静教室 +28dB 增益下实测 **零误触发**。

> ⚠️ **别靠调低 VAD 阈值来"更灵敏"**。实测 `threshold=0.2` 在弱信号下确实多触发,但 VAD 会
> 近乎恒为"有语音",句子再也断不开、只能靠 12s 硬切,**正常音量下反而丢词**(样本 78→63)。
> 灵敏度要补电平,不是降阈值。`vad.py` 里已留注释。

## 断句策略(为什么不会把从句切碎)

- **Silero VAD + 梯级静音阈值 0.70 / 0.55 / 0.45 秒**——英语从句/列举的换气停顿只有 250–400ms,
  阈值低于 0.45s 会把 "the mathematics **that**" 这类结构在关系词处腰斩,LLM 只能脑补 → 译文不知所云。
- **悬空半句缝合**:ASR 结果以连词/介词/冠词/助动词收尾且无句末标点时(`is_incomplete`),
  暂存不翻译,与下一段音频拼接后再送 LLM,保证每句都有完整主谓宾。
- **长句按逗号切**,不按词数硬切(避免劈开语法结构)。

## 延迟设计(为什么不会等 20 秒)

| 机制 | 作用 |
|---|---|
| **草稿即时译文** | partial 草稿每 ≥2.5s 且新增 ≥6 词 → 轻量翻译(无术语表/无上下文)→ **首个中文 ~3s 出现**(原先要等定稿 14s+) |
| **carry 硬上限** | 悬空半句挂起 >**5 秒**或 >**25 词** → 强制送出(末尾加 `…`),绝不让"等句子闭合"无限阻塞 |
| **长段早切** | 单句 >25 词按逗号切意群,逐句流式输出;定稿后正式卡片取代草稿 |

定稿仍是"完整句才翻译"(质量优先),草稿译文负责"先看懂个大概"。

> ⚠️ 草稿节流(`≥2.5s` + `新增 ≥6 词`)的**词数基准每句必须重置**。旧代码把上一句收尾的词数
> 带进新句,遇到**更短的下一句**(20 词 vs 30 词)时"新增 ≥6 词"永远不成立 → 整句拿不到即时中文,
> 「首字中文 ~3s」静默失效。现在每定稿一句就递增 `final_gen`,草稿线程见变化即重置节流。

## 已知限制

- **⚠️ GPU 驱动稳定性**:2026-09-10 本程序曾触发一次 `IOGPUFamily` 驱动断言内核崩溃(非 OOM;属 MLX 已知 bug 族 mlx-lm#883 / mlx#3186)。当前配置:`set_cache_limit(2GB)` 宽松缓存 + 不主动 `clear_cache`(避免 Metal 缓冲释放/重建竞态)+ 悬浮窗 25Hz 刷新。**跑本程序时不要同时开其他吃 GPU 的任务**;若换 backend(Ollama/llama.cpp)或不在跑 MLX 时仍崩 → 才怀疑硬件。
- **1.7B 翻译质量中等**:偶有误译或"过度修正"(如把正确的 "in relation to" 改成 "version 2";中文通常仍对)。
- 讲师完全不换气时靠 **12s 上限 + 标点断句**兜底(实测该片段 15s 内最长静音仅 0.4s)。
- 悬浮窗需图形界面会话;无显示时自动回退终端。
- 降噪(GTCRN)、Prompt Cache 未接入(前者需 A/B 实测,后者收益≈0)。
