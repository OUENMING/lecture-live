## 0. 一句话

这一层回答一个具体问题：**"草稿每秒重转一次、前面已显示的字偶尔被改掉"到底有多严重，
以及怎么量。** 现在有量具（离线回放）、有现场采集（真课 `.live.jsonl`）、有一份**完整真课**
的实测。**结论：改动里只有"现场采集"这一层被真课证明有用；草稿前缀冻结在真课上几乎没用。**

## 2. 这一层是什么

| 文件 | 作用 |
|---|---|
| `livemetrics.py` | 把 `main.drain()` 那个「用户实际看见了什么」的缝记成 `<会话>.live.jsonl`。**同时记 `raw`（模型原始假设）与 `text`（上屏的那份）** → 一次真课拿两条曲线 |
| `scripts/class_report.py` | 读那份 JSONL（或 `stream_eval --jsonl`，**同款字段**）出表：回改率 / K 曲线 / 延迟 / 腰斩臆造候选 / 多份按计数汇总 |
| `scripts/stream_eval.py` + `stream_metrics.py` | 离线回放量具（虚拟时钟、不排队）+ 纯函数指标（WER 归一化 / 回改率 / 分位数） |
| `draft_stable.py` | 草稿前缀冻结（LCP + 灰尾 K 词）。**默认关** |
| `draft_policy.py` | 草稿译文何时送翻译。`legacy` = 原内联判据（逐字等价），`clause` 是候选 |
| `system_tap.py` | 系统声源（CoreAudio Process Tap，替掉 BlackHole）。**CoreAudio 那段未真机验证** |

**硬前提**：`livemetrics` 绝不能影响上课（队列有界 + 后台写盘线程 + 每个方法吞异常）；
`draft()` 在主循环里只做 `put_nowait`，实测 **1.8 µs/次**。

## 3. ⭐ 全部实测数字

### 3.1 真课（生产真值）—— 2026-10-09 12:07 ECON10770，47.7 分钟

289 段 / **1906 份草稿** / 16173 个已显示词（另有 251 份因缓冲窗口滑动被剔除，占 22.5% 的词）。
`dropped: 0`（一份不丢）· `echo_retries: 0`（全程云端）· 13:22 已上传。

| 设置 | 回改率 | beyond-k | 相对基线 |
|---|---|---|---|
| 基线 | **36.6%** | 27.3% | — |
| 冻结 K=1 | **35.9%** | 26.6% | **−2.1%** |
| 冻结 K=2 | 36.8% | 27.3% | +0.4% |
| 冻结 K=3 | 37.7% | 28.1% | +3.0% |

草稿→定稿 **39.0%**。前 240 秒单看：25 段 / 196 草稿 / 基线 36.7% / K=1 34.3%（−6.5%）。

### 3.2 ⚠️ 生产 vs 回放：代理量具会把效应放大一个数量级

| 语料 | 基线 | K=1 | 谁更可信 |
|---|---|---|---|
| TTS（生产 `--source file` 真跑） | 10.2% | 8.7% | 与同音频回放 10.4%/8.9% **一致** |
| TTS（回放） | 10.4% | 8.9% | — |
| **真课 5 片回放**（98 段/846 草稿） | 40.9% | 35.4%（**−13%**） | 高估 |
| **真课 1 节生产**（289 段/1906 草稿） | 36.6% | 35.9%（**−2.1%**） | ✅ |

**⭐ 决定性对照：同一节课、同一段音频（10-09 那节的前 240 秒）两条路各跑一遍**

| | 段 | 草稿 | 基线 | K=1 | K=1 收益 |
|---|---|---|---|---|---|
| 回放（ffmpeg 解那段 opus） | 26 | 201 | **57.0%** | 44.6% | **−21.7%** |
| 生产（同一节的 `.live.jsonl` 切同一窗口） | 25 | 196 | **36.7%** | 34.3% | **−6.6%** |

→ **回放把回改率本身高估 55%（14 段/201 草稿 vs 25 段/196 草稿，分段规模几乎相同），
把冻结的收益放大 3.3 倍。** 根因：**回放喂的是归一化后的 16-bit wav（这次还多一道 opus
有损解码），生产喂 float**（`stream_eval.py` 文件头一直写着：从 wav 回放"17 段里 9 段改口"）
→ 回放把草稿本身弄得更不稳。**教训：代理量具能做相对比较，不能用来定"要不要开"。**

### 3.4 真课的形态与资源

- **断句 158 次里 132 次是 12s 硬切（84%）**；段长中位 9.9 s；**133/291 段撞 12s 上限**
  → **半句结尾是常态**（`carry` 拼接就是为它准备的），32.6% 的段落结尾没有句末标点。
- 录音电平：峰值 0.95 · RMS −14.9 dBFS · 块 RMS p5/p50/p95 = −29.6/−16.9/−10.2 · 动态 29.2 dB。
  **没有一段低于 −30 dBFS** → 电平不是退化原因（归一化器在干活）。
- 资源：**1.81 CPU-秒/音频秒**（占墙钟 164%）· 内存峰值 **3148 MB** · ASR p50 2496 ms / p95 3476 ms。
- 矫正：633 对里 174 对被改（27.5%），459 对原样。

### 3.5 腰斩臆造候选：这个判据**要降级使用**

10-09 真课 289 段里 74 段（26%）被判"定稿尾巴没有草稿支持"。逐条拆开看：
**40 条的尾巴一个生词都没有**（每个词这节课的草稿里都出现过 → 更像 **Parakeet 在这个位置漏词**）、
33 条"少数生词"、**只有 1 条"≥一半是生词"**；只有 1 条的尾巴能在**下一段**草稿里找到。

→ 它**主要在量 Parakeet 的漏词，不是 Whisper 的臆造**。当"值得听一眼"的粗筛可以，
**不能当幻听计数**。（TTS 那份能"精准命中一条"，是因为语料短、生词池小。）

## 4. ⭐ 结论：该用 / 不该用

| 项 | 判决 | 依据 |
|---|---|---|
| **现场采集**（`cl-x` 默认开） | ✅ **用** | 唯一被真课证明有用的那层；`dropped: 0`；成本 1.8 µs/次 |
| 草稿前缀冻结 `--freeze` | ❌ **不用** | 真课只值 −2.1%，K≥2 更差（代码留着：已验证、默认关、成本零） |
| 草稿译文触发策略 `--trigger clause` | ❌ 不用 | 请求只少 4%，且"句末未覆盖尾巴"多数片变差 |
| 系统声源 `--source system` | ⏸ 只对**线上课**有意义，且**未真机验证** | 先跑 `scripts/probe_system_tap.py` |
| 本地引擎后处理 | ⏸ 只在**断网降级**时生效 | 云端那条路根本不碰它（`cloud_translator` 有自己的方法） |
| 音频归一化上限（`PLAN-audio-gain` 步 3） | ⚠️ **值得继续做** | 真课 `capped 15.7%`、`gain_max` 贴死 30 dB（n=1 节课） |
| 输出报告 `--json` | ⚠️ 只在真要 JSON 时加 | 那一项是 O(n²) |

## 5. ⚠️ 已知缺口（**别声称做了**）

1. **生产真值只有 1 节课**（`live.jsonl` 全仓只有 1 份）。所以"冻结没用"是 n=1 的结论 ——
   方向明确（回放与生产差一个数量级），但**再上一节课就能加固或推翻**。
2. **`--source system` 的 CoreAudio 那段一行都没真跑过**（创建 tap 要授权框）。
3. **`echo_retries` 恒为 0** = "本地引擎没跑过"，**不是**"模型从不回显"。要测它得课后跑一次
   `--engine local`（MLX 有内核崩溃史，别在课上跑）。
4. **没有自动化的端到端判据**：`final_worker`/`partial_worker` 是 `run()` 里的嵌套闭包，
   默认闸门（116 条）**够不到它们** —— 见 §6.3 那次翻车。
5. **"臆造候选"的判据需要重做**（现在主要在量 Parakeet 的漏词，见 §3.5）。
6. 真课切片回放只切了 5 片（~20 分钟）；`sessions/` 里还有 **~57 分钟没切**
   （ECON10740.002/.004/.005、SOC10020×4 等）—— 但鉴于 §3.2，**继续堆回放样本的边际价值低**。

## 6. ⭐ 教训（可迁移的）

1. **分组错了会伪装成模型退化。** 两次：按"一句定稿"分组（一段 VAD 会被切成多句定稿）→
   `草稿→定稿` 从 10.7% 虚高到 **93.3%**；段号取自"定稿上屏时才自增"的信号（比段落真正
   结束晚 2–4 秒）→ 虚高到 **65%**。**数字难看先查分组，别先怀疑模型。**
2. **代理量具会把效用放大一个数量级**（回放 −13% vs 生产 −2.1%）。决定性数字只能来自生产。
3. **嵌套闭包里的 worker，默认闸门够不到。** 清理那轮把 `buf, _fseg = buf` 的拆包提到哨兵之前
   （"空转"那条路**每轮都走**）→ `final_worker` 线程当场死 → 没人消费 `finalq` →
   `partial_worker` 的"有定稿排队就让开"永远成立 → **整节课一份草稿都不出**；
   **3 份毫秒级判据 + 116 条闸门全绿**，只有 `--source file` 真跑抓到。
   → 动了 `finalq`/`streamq`/`drafts` 的元素形状或 `drain()` 的分发，**必须真跑一次**
   （命令见 `RESEARCH-stream-eval.md §9.4.1`）。
4. **判据要钉全部分支。** `audio_t` 我只钉了"缺席"那一半，在场那一半写成
   `u["start_t"] = u["start_t"] if …`（键还不存在）→ 一读离线 jsonl 就 KeyError。
5. **同一判据写两份 = 离线模拟预测的不是生产。** `append_only` 主循环手搓一份、
   离线模拟用 `stream_metrics.normalize` 又写一份，两份不等价 → 收进 `draft_policy` 一处。
6. **没人读的标量可能吃掉 99% 的运行时间。** 整课 WER 是 O(n²) 且每个 K 都算一遍
   → 一次报告 8 分钟（看起来像卡死）。**新工具出表前先量一次耗时。**
7. **改 `sessions` 软链时别的运行可能还活着** —— 我在另一次运行期间换了软链，
   漏了一个文件进真 `sessions/`。测试隔离要**读端和写端一起换**。
8. **别信"默认开 = 生效"。** 本地小模型后处理"默认就开"，但它只在本地引擎那条路上 ——
   全程云端时它一次都不执行。
