## §2 为什么

Owen 原话（2026-10-12）：

> 所有用户更新完这一个版本，Key 那一栏清空，然后提示说找作者拿 Key。

背景：通行码（3.9.2 上的）上线后，作者**收不回**已经散出去的原生 `sk-` key（那把只能去 DeepSeek 后台整个换掉），也**按不了人**计量。把这一栏清空 + 提示「找菠萝丁拿 key」，是客户端这边唯一能把大家换过来的手段。

## §3 怎么做（实现要点，含那些"看起来怪但有理由"的地方）

### 3.1 `keyentry.clear_legacy_key()` —— 三条纪律

```python
def clear_legacy_key(*, root=None, version=CLEAR_VERSION) -> dict
# → {"done": 标记写成了没有, "moved": [落点…], "first": 这次是不是头一回做}
```

1. **只挪不删** —— 落点是同目录的 `credentials.bak-3.9.3`（`os.rename` 同盘原子，权限 600 原样带过去）。用户想找回自己那把 key，改个名就是原来那个文件。
2. **绝不碰通行码** —— 值以 `cl-` 开头的**跳过**。这是**安全网**：即使标记丢了、这次搬家又跑一遍（换机器、用户手滑删了状态目录），已经配好的通行码也**不会被误伤**。
3. **标记最后才写** —— 中途失败就下次启动重试，**不谎报"做过了"**。

### 3.2 标记为什么住 `~/.classlive/key-cleared` 而不是安装目录

安装目录会被 `git pull` 重写。**标记一丢，那次搬家会再跑一遍** —— 而那时用户早就填好新的通行码了（虽然有纪律 2 兜底，但那次搬家还是会白跑）。同 `paths.ready_state` 那条「用户的决定不能住会被清掉的地方」。

### 3.3 `first` 字段存在**只为判那张一次性弹窗**

弹窗的条件是 **`first and moved`** —— 恰好是「**这台机器上真的有一把 key 被挪走了**」。它天然只发生一次（版本标记挡着第二次），而且用户把备份恢复回去之后也**不会**再弹。

三条"不该弹"全靠这一个判据挡住：新用户（`moved` 空）、已配好通行码的（`moved` 空）、第二次启动（`first` 为 False）。**别放宽成"看版本号"** —— 那会把本来就没 key 的人一起拦一下，而他们什么都没失去。

### 3.4 弹窗的位置与时机（Owen 明确要求"注意好时机和逻辑"）

- 放在 `entry_launch.main()` 里、**`entry_panel.open_panel()` 之前**。⚠️ 这个顺序有判据钉着：就绪条「翻译引擎」那一格读的是 `keyentry.has_any()`，搬家排在后面的话面板会一口咬定"配好了"，而一开课翻译其实是断的（界面撒谎是本仓最忌的那类）。
- 此刻没有课在录、没有音频在采、没有模型在加载 —— 模态框挡不住任何活。
- `cl` 那条路在终端里已经被 `main.run()` 打了一行字，不弹框。
- **不会被判据挂住**：`notice.alert` 只在 `CLASSLIVE_FROM_APP` 设了才弹（双击 `.app` 那侧），终端 / 管道 / 判据里它只 `print`。

### 3.5 草稿模型：为什么"判据只有一份"

`update.spawn_draft_model_download()` 起一个 `start_new_session=True` 的独立进程跑 `update.py --run-step draft_model`。**「这台机器要不要它」不在这里判** —— 落在 `run_step(DRAFT_MODEL)` 里（`doctor.model_present` + `draft_engine.want_model`），所以那个步骤是**幂等**的，两个调用方可以无条件叫它。

- 调用点两处：`main._draft_model_on_exit()`（**下课之后**，排在 `_auto_update_on_exit()` 之后）与 `entry_launch`（**只在 `rc["code"] == CANCELLED`**，即关掉面板没开课 = 空闲）。
- ⚠️ **上课途中绝不下**（Owen 定的）：464 MB 会和云端定稿的音频上传抢同一条教室 Wi-Fi，而那正好压在最不该压的时刻。
- 两处**共用** `CLASSLIVE_NO_AUTO_UPDATE` 那道闸 —— 判据里必须一起关掉，否则跑一次测试就真去下 464 MB。复用而不是新开开关，也让 `docs/HANDBOOK.md` §6.1 的登记表不增项。

### 3.6 `notice.build_alert()` 为什么抽出来

`alert()` 自己会 `runModal()`（阻塞），截图探针不能走它。抽出来之后 `scripts/probe_keyreset.py`（新）与生产**同源**，截出来的就是真实界面。同 `build_text_alert` 那条纪律。

## §7 顺手查清的两件事（免得下一个人重新查）

### 7.1 `cl-` 通行码的钱从哪出

```
cl- 通行码 → Worker（asr.bldcam.page）→ Worker 用 env.DEEPSEEK_KEY 打 DeepSeek
sk- 原生 key → 客户端直连 DeepSeek（不经 Worker）
```

- **Worker 上那把 `DEEPSEEK_KEY` 已于 2026-10-12 重放成 `~/.classlive/credentials` 里那把**（Owen 自己跑的 `npx wrangler secret put DEEPSEEK_KEY < ~/.classlive/credentials`）。
- ⚠️ **Cloudflare secret 的值读不出来**（只写的，`wrangler secret list` 只给名字）。想知道是哪把**只能重设**。三秒的事，别去 shell 历史里翻。
- ⚠️ 由此产生一个耦合：**两条路现在用的是同一把 key**。哪天去 DeepSeek 作废它，所有通行码会一起断。Owen 说他有第二把（"一把国内站一把国际站"→ 后更正为"**只是区分用户用的**"），打算 Worker 一把、自己留一把。

### 7.2 「本次更新」卡片为什么每次上课都弹

`main._whatsnew_payload()` 的 docstring 写着（**2026-09-25 按作者要求重定**）：

> **不勾「本版本不再提示」→ 每次启动都弹**，直到勾了它。

判定用 `.update-skip`（值存版本号，所以新版本自动重新开始弹），跟 `.update-seen` 无关。**想让它安静 = 勾一次卡片上那个勾**。
它弹在悬浮窗上（`overlay.show()` → `_show_whatsnew_card`）也是刻意的：非模态、不挡转录；挪到 `main.run()` 开头会带宿主 Python 的图标并在 Dock 里冒出来。

## §9 踩过的坑（跨项目可复用）

1. **判据假绿**：给 `_EngineWarns` 写的并发判据，**去掉锁照样全绿**。往下量才发现那个形状在 CPython 里**根本打不到**（`str.join` 对 dict 视图的迭代是一段不放 GIL 的 C 循环）。→ **新判据必须做变异验证**，并且**变异红了才算数**。

4. **我自己的引号 bug 犯了三次**：中文文案里嵌 `"…"` 时写进 Python 字符串 → `SyntaxError`。写测试断言含中文引号时，用「」。

6. **macOS `ps` 默认按屏宽截断 command 列** → 我的会话探针查出空表，一度以为产品坏了，其实是**量具坏了**。用 `ps -eww`。
7. **探针一定要先拍基线**：`screencapture` 在显示器睡着时拍出纯黑，和"界面没渲染"长得一样。`probe_*.py` 里都有这条。

### 11.7 本轮拍板与"下一版"候选（Owen 2026-10-12 夜）

- **草稿模型（Nemotron 464 MB）**：保持 **3.9.3 的行为** —— 退出时自动下、**不算硬缺失**（不装也能上课，
  就绪条与 `cl doctor` 语义不动）；**12 GB 内存门保留**（`draft_engine.MIN_RAM_BYTES`：<12 GB 的机器
  装了也用不上，`choose()` 那层照样选 parakeet）。本机（16 GB）实测 `want_model()=True`、模型已在位。
- **Parakeet（640 MB）不删**。它不只是"旧草稿模型"，还身兼：① **本地定稿引擎** ——
  Whisper 是可选的、默认没装，于是断网 / 关云端时的定稿**就是它**（`final_asr.load_final(local=whisper or None, draft=parakeet)`）；
  ② 流式模型熔断后草稿的兜底（`DraftEngine` 里那条 `fallback_reason`）。
- **"流式模型当定稿"是 P2，不是配置项**（Owen 问了"现在的流式模型不能当定稿吗"）。三个坎，
  都是实测/文档里已有的：
  1. **必须补尾**：`input_finished` 前不补静音会吞掉段尾近 1 s 的词（20 段 WER **16.2% → 补 2.0 s 后 10.3%**），
     而补的零要真解码 —— 按 RTF ≈ 0.15 算每段 **+约 300 ms**（`PLAN-streaming-asr.md` §0.1 明确纠正过"只花 20–30 ms"）；
  2. **质量没量过**：Nemotron 现有数字全是**草稿角色**（回改率/延迟），"当定稿"的 WER 没人测；
  3. **接口**：定稿链每段要 `transcribe_lp(samples)`（文本+logprob 一次给，`main.py:1724` 的 testmode 吃它），
     而流式那层只有增量 partial（`transcribe(buf, tag)`）。
  → 顺序应当是：先做 P2（流式当断网定稿）→ 拿真课录音量一轮（对照现在这条链）→ 再谈删 Parakeet。
  ⚠️ 本地定稿**只在断网/关云端时才用** —— 换掉它等于在最需要可靠的时刻换上一个没量过的引擎。

### 11.8 焦点守卫那一条的前后经过（本轮最绕的一处，写给下一个人）

1. **原缺陷**（第二轮 OCR 报的）：`_focus_guard()` 定义完立刻调一次，而窗口上屏
   （`orderFrontRegardless()`）在一千行之后 → 首拍 `isVisible()` 为假 → 那一版直接 `return`，
   **连末尾的 `callLater` 一起跳过** → 链子从没接上，"只有真在编辑才允许 key"这条不变量**一次都没生效**。
2. **第一版修法**（把起链点搬到上屏处、`seen`/`waits` 区分"还没上屏"与"已经关掉"）：
   ⚠️ **我自己踩了第二条坑** —— 守卫是 `build()` 里的闭包，`AppHelper.callLater` 会把**闭包连同它闭进来的
   `win`** 一起挂在 run loop 上；而没有 run loop 的场景（测试）里那一拍**永远不会执行** → 每开一次面板
   钉住一棵视图树。**`tests/test_panel.py` 第 ⑧ 节当场量到**：3 轮 vs 9 轮 `[144, 153]`（基线 `[142, 142]`）。
   → 教训：**定时器的回调里不许闭住窗口**（同族：`_status` 查 `S["panel"]` 而不是捕获某一代）。
3. **最终形状**：一拍 = 模块级 `_guard_tick(state, gen)`，`state` 只放纯数据
   `{"win", "gen", "waits"}`；三个收手条件 —— `win is None`（`do_close` 的取消令牌）、
   `gen` 对不上（上一代的链子）、不可见且等满 `_GUARD_MAX_WAITS`（兜底，10 拍 = 5 s）。
   `open_panel()` 复用那条路也重上链（那是我第一版记为"已知缺口"、质检代理指出可以顺手补上的）。
4. **判据**：`tests/test_entry_panel.py` ⑲d 用**假窗口 + 假 `callLater`** 钉五个行为（该放开 / 编辑时不碰 /
   关了收手 / 上一代收手 / 等满上限收手），变异验证过（去掉 `gen` 或上限 → 红）；**真窗口**那版在
   `scripts/probe_ui_guard_status.py`（上屏后 `waits=0`、手动 key 后 1.5 s 内 `isKeyWindow` 变 False、
   `close()` 后 `guard_win` 变"无"）。
