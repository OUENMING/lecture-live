## 5. 我认为重要的信息

### 5.1 只有**真跑**才看得见的坑（动手前扫一眼）

1. **`_layout()` 只在尺寸/档位变时跑** —— `_sync_panel_size` 是**轮询**，尺寸没变就早退 → 章节条**永远不出现**。修法：`summary_update` 末尾自己补一次。
   ⚠️ **探针里看得见、真跑里看不见**。
2. **滚动后回收池不重算** —— 两个滚动方法都会**回写 `_expected_origin`**（防误判成用户滚动），代价是 `tick()` 看不出视口动过 → 槽位停在旧位置 → **整屏空白**。修法：滚完补 `mark_dirty(urgent=True)`。
3. **模块级函数插在类体中间 = 类体到此结束** —— 后面的方法全变成模块级函数。⚠️ **`ast.parse` 照样通过**（语法合法），**只有测试拦得住**。
4. **`NSMenu.autoenablesItems` 会覆盖 `setEnabled_(False)`**（实测）→ 改用 `setAction_(None)`。
5. **`CLASSLIVE_LIVE_SUMMARY` 阶段 4 起默认 `"1"`**（想省 API 调用 `=0 cl`）。
6. **关闭后拒写要两层都补** —— 见 §3.4。
7. **「一条纪律两处定义」** —— 见 §3.5。

### 5.3 方法论：这一轮抓到的假绿形态

- **夹具里的对象「缺那个字段」→ 被测的那个分支永远不触发** ⭐⭐
  造夹具时问：**「这个字段如果缺了，我要测的分支还走得到吗」**。`en` 档那条判据的夹具里原子**没有 `zh`** → `_atom_big` 看不看 mode 结果一样 → **三个 bug 一起藏了很久**。
- **变异验证自己也会假** ⭐⭐
  我写「删掉 `if self._closed` 判」的变异脚本时，实际替换的是它**上面那两行注释**，只插进一段 `if False:` 的死代码 —— **守卫原封不动**，判据当然不红。**变异必须改到那一行本身**，并确认行为真的变了。
- **「条件变了、读数却没变」= 先去看图确认条件真的变了。**
