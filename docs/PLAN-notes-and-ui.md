## 0. 病根诊断（已实测，勿重新推翻）

作者原话：**「Key Concepts 每一段的那个总结然后翻译，有点像把教授说的话再翻译出来，感觉并没有什么用处。」**

**这不是感受问题，是 prompt 自己写死的。** `obsidian_writer.py:61` 的 `REVIEW_SYS`：

```
用户给你一节课**一段**的逐句中英对照转录。你只依据转录内容输出, 绝不引入外部知识、绝不猜测。
...
- 只写转录里确实讲过的内容; 拿不准就不写。
```

**"绝不引入外部知识" + "只写转录里确实讲过的内容" → 模型只能复述。**
它写出 `The lecturer states that if you hate landlords...` 是**严格执行指令**的结果，不是偷懒。

于是每条 point 变成：**教授说过的话（英） → 同一句话换个说法（英 detail） → 再翻成中文（zh）**。
**三段同样内容，零新增信息。**

⚠️ 那条约束本身**不能删** —— 它是防幻觉的，学生要信这份笔记。**要拆的是"事实"与"理解"**：
教授说了什么（必须忠实）vs 这为什么重要 / 怎么用（要有依据，但**必须标明来源**）。

### 两处放大这个病的东西

| 放大项 | 位置 | 后果 |
|---|---|---|
| **只用转录，不喂课件/教材** | `_call_review` 的入参只有转录行（`obsidian_writer.py:400`） | 模型**没有**外部知识可用 —— 想加值也没料 |
| **分块调用、块间互不知情** | `REVIEW_CHUNK` 切块后逐块调（`obsidian_writer.py:402-417`） | 同一概念在不同块各写一遍；全课没有"编辑"这一步 |

### 渲染层**没问题**（别改）

`obsidian_writer.py:539-553` 的结构是对的：`**主张**` / `细节` / `· 中：` / `· 🔑 术语`。
**问题 100% 在 prompt 的 content 指令上。**

## 2. 阶段 A：笔记复习层重做

### 2.1 要实现的

**① 拆开"事实"与"理解"，并标来源。** 每条 point 从三段同义内容改成两类：

| 字段 | 是什么 | 来源纪律 |
|---|---|---|
| `en` + `detail_en` | **教授在这节课上确实讲了什么** | 只能来自转录（保留现在的"绝不猜测"） |
| `zh` | 中文点睛（**不是翻译**） | 同上 |
| **`why`（新增）** | 为什么重要 / 怎么用 / 常见误解 | **允许用课件与教材**，但**必须带来源标记** |

渲染时 `why` 前面挂一个来源标签（如 `📖 课件` / `📚 教材 p.12`），
**和转录来的内容视觉上分开** —— 读的人一眼能看出哪句是教授说的、哪句是补的。

**② 把课件喂进去。** `Study/<课号>/materials/` 里已经有现成的（实测：
SOC10020 有 22 份 908K，含教材章节 / slides / syllabus；ECON10740 有 14 份 152K；
单份 slides 仅 **7KB**，教材单章 56–184K）。

- **先做小的**：slides / syllabus / module-descriptor（几 KB，直接塞得进 prompt）
- **后做大的**：教材章节（56–184K，要检索而不是整份塞）

**③ 跨块合并同一概念（最小版）。** 现在每块独立摘要、同一概念写两遍。
最小改动是**在拼装后加一趟"合并同义小标题"**，不重构整个流程。

### 2.2 依据（file:line）

- `obsidian_writer.py:61` —— `REVIEW_SYS`，病根
- `obsidian_writer.py:400` —— 拼转录行的唯一入参
- `obsidian_writer.py:402-417` —— 分块循环 + 结果拼装（合并步骤插在这里之后）
- `obsidian_writer.py:539-553` —— 渲染层（**不改**，只加 `why` 一行）
- `polish.py` —— `_overview` 已有"多块时重写一份全课概览"的先例（`obsidian_writer.py:418-424`），
  "跨块合并"照它的形状做

### 2.3 三条低成本探针（**先做这三个，再决定要不要重构**）

调研结论明确建议这一步，理由是市场领先者都没走全局重组那条路（见 §4）。

#### 探针 1 已跑完 —— **结论：换框架不管用**（2026-09-25 实测）

两节真实课做 A/B（同一批句子、只改框架那一句、其余逐字不动）：

| 课 | 版本 | point | **离题率** | `detail` 填充率 |
|---|---|---|---|---|
| ECON10740 | old | 21 | **38%** | **21/21 = 100%** |
| | new | 20 | **60%** ⬆️ | 20/20 |
| SOC10020 | old | 19 | **5%** | **19/19 = 100%** |
| | new | 13 | **8%** ⬆️ | 13/13 |

**三条结论**：

1. **换 prompt 框架不管用，甚至略差**（离题率反而升）。
   → **探针 1 判定无效，不再投这条。**
2. **`detail` 字段一直在正常生成**（100%）。
   ⚠️ 我一开始报「detail 全空」是**我的探针读错了键**：`_clean_review` 把 `detail_en`
   映射成 `detail`，我读的是 `detail_en`。**量具自身出错，这是第 3 次。**
3. **离题率高度依赖那节课本身** —— 同为旧 prompt，一节 38%、一节 5%。
   **因为 ECON10740 那节开头就是图书馆导览**（楼层座位 / 开放时间 / 翻新噪音），
   而这些**原样进了「知识点详解」**。

→ **病根不是 prompt 的措辞，是「没有『什么值得记』的判断」。**
   这也说明探针 3（跨块合并）**治不了主要症状** —— 缺的是**先做取舍**（§0 的"缺编辑"那层）。

#### 探针 2 / 3 状态

- **探针 2（喂课件）** —— 等 §7-A（`materials` 路径约定）做完才有素材可喂
- **探针 3（跨块合并）** —— 探针 1 的结果显示它治不了离题，**优先级下调**

# 明细落 /tmp/review_ab.json —— **必须人工复核**（词表只是粗筛）

真实病征是**直接抄转录**，不是那个句式。判据已换成「离题率 + detail 填充率」。

#### 怎么跑（实操）

**已确认可跑**：`.deepseek_key` 在仓库里（35 字节），`obsidian_writer` 会读它。
探针**不需要改架构**，只要一个「只跑生成、不跑录音」的入口：

```bash

```

⚠️ **改 prompt 时不要在生产路径上做 A/B** —— 那会同时改掉你在用的行为。
正确做法：**新旧两版各跑一次同一节课，把两份 `Key Concepts` 存成文件人工对比。**

#### ⚠️ 判据必须先定、且探针自身要先自测

按本项目硬规矩 `measure-before-claiming`（"验证器自身也要先自测"）：

| 指标 | 怎么算 | 注意 |
|---|---|---|
| **复述率** | 含 `The lecturer states` / `the lecturer said` / `professor` 等模式的 point 数 ÷ 总 point 数 | **判定规则要人工核一遍**，不能靠感觉 |
| **信息增量** | `why` 里**转录中没有的**信息条数 | 靠人判断，抽查 5 条 |
| **重复率** | 跨块合并前后，"同一概念出现两次"的条数 | 探针 3 专用 |

**并且要先证明量具能分清好坏**：拿一条已知的复述型（`The lecturer states that if you
hate landlords…`）和一条已知的整理型各放一条，人眼确认判定规则能把两者分开。
**还要带噪声带** —— 同一节课跑两次的波动是多少？不知道波动就说不了"下降了"。

### 2.5 反模式护栏

- ❌ **别删"绝不猜测"那条** —— 它防幻觉，学生要信笔记。要加的是**有来源的补充**，不是放开瞎编。
- ❌ **别让 AI 补充混进"教授说过的话"里** —— 两类内容必须可区分，否则笔记的可信度整个塌掉。
- ❌ **别一次上全局重组**（原子提取→全课重组）—— 调研显示市场领先者都不走这条路，

- ❌ 别在直播路径上调 LLM —— 笔记是收尾的事。

## 3. 阶段 B+C：ClassLive 接管 Study/（含取消 skill 入口）

### 3.1 能自动化的边界（**这是本阶段最重要的一张表**）

| `Study/` 里的东西 | ClassLive 收尾时能不能生成 | 为什么 |
|---|---|---|
| 本节课的新卡片（中→英） | ✅ **能** | 手上有转录 + 术语表 |
| 新的待入库题目 | ✅ **能** | 就是现在 `❓ Review` 那块 |
| 考点总表的增量 | ⚠️ **部分** | "哪些是考点"需要**课程上下文**（Quiz 范围 / 课件），ClassLive 只有录音 |
| **错题本的状态更新** | ❌ **不能** | 它不知道**你答错了什么** —— 那是你的动作 |
| **复习排程的下次日期** | ❌ **不能** | 依赖"你这次复习得怎样"（`✓稳/~糊/✗忘`） |

**所以能接管的是"这节课产出了什么"（只增），不是"你学到哪了"（要人输入）。**

这正好对上 `Study/SOC10020/题库与错题本.md` 自己写的规矩：**「只增改，不整体重写」**。

### 3.2 依据

- `Study/SOC10020/题库与错题本.md` —— 现有的"只增"规则与分区（错题本 / 待入库 / 缺口）
- `Study/SOC10020/cards.md` —— 格式 `中文 | 英文 | 来源`，方向固定"中→英"
- `Study/SOC10020/复习排程.md` —— 间隔算法（Cepeda 2006），**状态是人填的**
- `obsidian_writer.py` 已经会写 `Lectures/`；本阶段是**再写一处** `Study/`

### 3.3 验证清单

- [ ] 跑完一节课后，`Study/<课号>/题库与错题本.md` 的「待入库题目」多了本节课的题
- [ ] **错题本与复习排程一个字都没被动机器改** —— 它们是人的领域
- [ ] 同一节课重复跑两次**不产生重复条目**（幂等，靠时间戳去重）
- [ ] 没有 `Study/<课号>/` 目录时不报错（只写 `Lectures/`）

### 3.4 反模式护栏

- ❌ **别让机器改错题本 / 复习排程** —— 那两处记的是**人的状态**，机器写进去就是伪造。
- ❌ 别整份重写 `Study/` 的文件 —— 只追加/只更新自己那一节。
- ❌ 别自动装 Obsidian 插件。**而且按 §7.1 的调研结论，根本不该依赖插件**：
  折叠 callout（`> [!faq]- 问题`）就能做"猜→揭晓"，Bases / Canvas / Properties 都是核心插件。
  **顺带修一个空头支票**：`Lectures/` 的笔记里现在写着「可被 Spaced Repetition 插件识别」，
  **而该插件作者自己都没装** —— 要么改成折叠 callout，要么注明"需自行安装"。

## 4. 调研结论（2026-09-25）

### 4.1 "分块→摘要→拼接"的缺陷有正式名字

- **inter-chunk dependency / inter-chunk conflict**（LLM×MapReduce, Chen et al.）——
  正是"块与块互不知情、同一概念两处各写一次"
- **lost in the middle**（长输入中段被忽略）
- ACM Computing Surveys 长文档摘要综述：「长文档摘要不可避免的信息损失」

### 4.2 "原子提取→全课重组"有学术支撑

| 工作 | 会议/年份 | 与我们的关系 |
|---|---|---|
| **Reconstruct Before Summarize (RbS)** | EMNLP 2023 | **专做会议转录**，先重建要点再摘要 —— 与两段式几乎同构 |
| SummN | ACL 2022 | 多阶段 split-then-summarize，自称"first multi-stage framework" |
| Two-stage Summarization for Long Dialogues | arXiv 2410.06520 (2024) | 两阶段，**明确覆盖 lectures** |
| Topic Segmentation + 图结构 | CCL 2025 | 先按主题聚类再摘要，专治"话题快速切换" |
| **Atomic Content Unit (ACU)** | arXiv 2303.03608 | 把文本拆成原子信息单元作中间表示 |

### 4.3 ⚠️ 但市场领先者**都不走这条路** —— 这是最重要的反向发现

> **Granola 官方博客自己写出了这个批评**：
> *"Most productivity tools promise to automate your meeting notes entirely.
> **The result is usually a summary that captures volume but loses judgment**."*
> *"AI models prioritize summary content based on **word frequency and topic recurrence,
> not strategic importance**."*

**但它的解法不是"加一个全局重组阶段"，而是 human-in-the-loop**：
用户会上边听边记关键词，AI 拿那些关键词当锚点去全文抓相关内容。
官方原话：*"Leave the notepad blank and the output reverts to a generic summary."*

**中文产品同样**：通义听悟的纪要是"核心议题（**按讨论顺序**）"；飞书妙记是"**章节化分段**"
+ 待办识别 —— **都是时间轴骨架，没有按概念重组**。

**解释（推测，未验证）**：不是他们没想到，而是**没有人工锚点时，全局重组的取舍质量不稳定**，
所以他们宁可让人类在当场给判断。

### 4.4 Cornell 类比只对一半

Cornell 是 **5R**：Record → **Reduce** → Recite → Reflect → Review。
官方材料写明 **Reduce 是"课后尽快"做的独立一步**，所以"记录与整理是两步"这个类比**成立**。
**但后三步是学生自己出声复述、自己反思、自己间隔复习 —— LLM 替不了。**
三段式只对应到前两步。

### 4.5 ⚠️ 一条反向证据（必须记）

**Microsoft Research 2025 汇总的 344 人 RCT**（Goldstein et al. 2025）：
传统自己做笔记在**保持 / 理解 / 自由回忆**三项上**全部优于**"有 LLM 辅助做笔记"。

**⚠️ 口径**：那些实验比的是"学生**自己**记笔记 vs 有 LLM 帮忙记"，
**没有一组是"LLM 生成笔记给学生事后读"** —— 那才是本产品的形态。
**所以不能直接搬来当反证**，但它指向一个真实风险：**AI 笔记可能制造"学会了"的错觉**。
→ 落地含义：复习层必须**逼人回忆**（折叠、自测），不能只是"读起来很完整"。

## 5. 阶段 D：UI 动效（调研已完成）

### 5.1 草稿→定稿的"跳" —— **有正式名字，而且这个架构有专门的论文**

| 项 | 内容 |
|---|---|
| **指标** | **UPWR**（unstable partial word ratio，"已解码的词里被后续输出改掉的比例"）+ **UPSR**（修订发生频率）。Shangguan et al., Interspeech 2020 |
| **架构同构的论文** | **arXiv 2312.09463《Partial Rewriting for Multi-Stage ASR》(2023-12)** —— 原文 *"a **small left-context only model** creates streaming results and a **larger left- and right-context model** produces a final result at the end"*。**这就是 Parakeet 草稿 + Whisper 定稿。** |
| **那篇的贡献** | 不是替换，而是**把两个模型的输出合并**：*"improves streaming results by ~10%, without altering the final results… **introduces no additional latency and reduces flickering**"* |
| **业内标准做法** | **LocalAgreement**（`ufal/whisper_streaming`）：只提交**连续两次解码一致**的前缀；**Soniox 官方 wiki**：*"尾部仍是临时态可被替换，前面某点之后全部冻结"* |

⚠️ **但有个前提差异，不能照搬**：LocalAgreement 比的是**同一个流的连续两次输出**；
ClassLive 是**两个不同模型**。所以那套"等两次一致"的判据不直接适用。

### ⚠️ 所以第一步不是改 UI，是**先量**

`sessions/` 里有历史会话文件，草稿与定稿**都在里面**。算**词级编辑距离的分布**即可：

- 若中位只差几个词 → **"跳"很轻，不值得做 diff**
- 若经常整句重排 → 高亮也救不了，得靠**冻结前缀**（LocalAgreement 那类协议）

**这是半小时的事，而且它决定后面要不要做。不测就做是赌。**

### 5.2 面板 resize 的动画 —— **用 `setFrame:display:animate:YES`，不要 `animator()`**

| 事实 | 依据 |
|---|---|
| `animator()` 要求当前线程有 duration > 0 的 `NSAnimationContext` | Apple 官方文档 |
| CA 隐式事务在 **run loop 迭代时**自动提交 | `CATransaction` 文档 |
| 项目 pump 用的是 `kCFRunLoopDefaultMode` | `NSAnimation.runLoopModesForAnimating` 默认含 `NSDefaultRunLoopMode` |
| **⚠️ `setFrame:display:animate:YES` 走另一条路** —— *"ignores NSAnimationContext entirely and uses its own fixed timing"*，时长由 `animationResizeTime:` 定 | Apple 官方文档 |
| **苹果对自建 run loop 的警告** | `NSApplication.run()` 文档：*"**This a critical and complex task, however, that you should only attempt with good reason**"* |

**结论**：`animator()` **很可能能用**（pump 确实在迭代 default mode），
**但 `animate:YES` 风险更低** —— 它自带计时器，**完全不依赖 run loop 的 pump 行为**。
代价是时长不可控。

另一条约束：动画要让 **layer-backed** 视图才顺（`setWantsLayer:YES`）——
项目部分视图已经是，**不是全部**，要先查。

### 5.3 风险对比（**②比①大，而且原因不对称**）

| | 值得做？ | 风险 |
|---|---|---|
| **① 词级 diff** | **先测再定** | 低 —— 纯显示层，改坏了只是难看 |
| **② 动画过渡** | **值得**，但用 `animate:YES` | **中** —— 若 `animator()` 在自建 loop 下半途卡住，面板会**停在中间尺寸挡住字幕**，那是**可用性事故**，不是难看 |

### 5.4 验证清单

- [ ] 先出**编辑距离分布**（词级，草稿 vs 定稿），带样本量 —— 这个数字决定 ① 做不做
- [ ] 动画若做：展开/收起期间的**帧时间直方图**，用 `probe_scroll.py` **同一套 8.3ms 闸门**
- [ ] 动画结束后面板**尺寸精确**（不能停在中间）—— 这是 ② 的硬成功判据
- [ ] 全部 layer-backed 视图确认
- [ ] `probe_scroll.py` 仍通过（滚动不能被动画改坏）

### 5.5 反模式护栏

- ❌ **别在没量编辑距离之前做词级 diff** —— 那是赌。
- ❌ **别用 `animator()` 做 resize** —— 自建 run loop 下它的行为依赖 pump，
  半途卡住会挡住字幕。要控时长再说。
- ❌ 动画不得阻塞 pump —— 参考 `PUMP_IDLE_S` / `PUMP_ACTIVE_S` 的既有取舍。

## 6. 课件 / 教材联动（头脑风暴，2026-09-25）

### 6.1 手上已有什么（实测）

作者的 vault 里 `Study/<课号>/materials/` 已经有：

| 类别 | 实例 | 特点 |
|---|---|---|
| **周次/主题课件** | `week1-crisis` · `week2-communicating-ideas-slides-26-fin` · `w4-jacobs-city-neighborhoods` · `theme2-sociology` | **按周命名 → 天然能跟日期对齐**，且小（slides **7KB**） |
| **教材章节** | `wade-ch1-the-self` (64K) · `wade-ch3-our-identities` (88K) · `wade-glossary` | 权威定义，但**大 → 要检索，不能整塞** |
| **学术论文** | `collins-2001-…` · `connell-2009-…` · `giddens-et-al-2014-…` | 课后深度阅读 |
| **考核定义** | `_ucd-module-descriptor` · `assessment-portfolio` · `outline-2026` | **说了考什么、怎么考** |
| **嘉宾讲者** | `week3-fiona-mcmanus-…` · `week3-richard-otroshchenko-dcee-economist` | ⭐ **文件名就是人名** |

规模：SOC10020 有 22 份 908K；ECON10740 有 14 份 152K。

### 6.2 ⭐ 最有价值的一点：Slides 是「教授认为什么重要」的代理指标

这是 ClassLive **单靠录音永远答不出**的问题 —— 而素材里就有答案：

```
                     slides 里有          slides 里没有
  教授讲了很久   ① ✅ 核心内容            ② ⚠️ 补充/闲聊/板书
                    → **优先做复习卡**       → **降权**
  教授没讲       ③ 🔥 **考点，但你漏听了**  ④ —
                    → **最该补的**
```

**第 ③ 格最有价值** —— 它把"你漏听了什么"变成可计算的。教授发了 slide 却没讲，
通常意味着"自己看"或"下周考"。

**这正好解决 §2 里那条悬着的问题**：「哪些是考点」单靠录音答不了 —— 与课件对比就能答。

### 6.3 联动方式：五层，成本递增

| 层 | 做什么 | 成本 | 要 LLM |
|---|---|---|---|
| **L1 标注来源** | 每个 Key Concept 挂上对应的 slide 页码 / 教材小节 | 极低 | **不要** |
| **L2 喂 slides 写 `why`** | slides 当"为什么重要"的来源 | 低 | 要 |
| **L3 教材做段落检索** | 教材章节按段落取用（不是整塞） | 中 | 要 |
| **L4 差异检测** | §6.2 那张四格表，标出"课件提到但课堂未展开" | 中 | 要 |
| **L5 从习题生成题库** | `tutorial1-practice` / `assessment-portfolio` → 题库 | 低 | 要 |

**建议顺序：L1 → L2 先做**（零/低成本，且能让 `why` 第一次有真东西）。
**L4 价值最高但最容易做错**，单独列为待验证项，见 §6.6。

### 6.4 对齐机制：怎么知道「这节课」对应「哪份材料」

三条路，从稳到弱：

1. **文件名前缀** —— `week1-` / `w4-` / `theme2-` 直接给周次或主题
   （实测 ECON10740 与 SOC10020 **都是这个规律**）
2. **`outline-2026` / `_ucd-module-descriptor`** —— 里面列了每周主题与日期，
   把"周"映射到"日期"
3. **术语重叠度兜底** —— 转录里的术语 vs 材料的术语算重合率（周次缺失时用）

### 6.5 ⭐ 嘉宾讲者：一个免费的强锚点

`week3-fiona-mcmanus-…` / `week3-richard-otroshchenko-…` —— **文件名里就是讲者名字**。
那节课有两位嘉宾，转录里能看出换人（语气/内容突变），但**我们没做说话人分离**（已否决，太重）。

**折中**：把讲者名字喂给 LLM，让它**按主题切分而不是按时间切分** ——
名字对不上的段落归为"嘉宾部分"。**零新基建。**

### 6.6 ⚠️ 两个必须认账的约束

1. **教材单章 56–184K，塞不进 prompt** → 必须**段落级检索**。
   vault 里的 `smart-connections` / `omnisearch` 是 Obsidian 插件，**ClassLive 用不了**。
   **简单版**：按术语 / 小标题做关键词匹配抽段，不需要 embedding。
2. **L4 的"漏听"判定会误报** —— slide 有但教授口头略过是常见的。
   **必须做成"提示"而不是"判定"**：标签写「课件提到，课堂未展开」，
   **不写「你漏了」**。同理，这条要**先有一个可验证的人工样本**才能上。

## 7. 多用户：朋友的资料怎么进来（调研已完成）

### 7.1 ⭐ 决定性发现：**不装任何社区插件也能做**（2026-09-25 调研 + 本机核实）

> **Obsidian 1.9.10（2025-08-18）把 `Bases` 升为核心插件** —— 官方的 Dataview 替代品。

**本机核实**（`~/.obsidian/core-plugins.json`）：`bases` ✅ 与 `canvas` ✅ **都在核心插件列表里**。

| 需求 | 原生方案（**0 安装**） |
|---|---|
| 表格 / 数据库视图（原以为要 Dataview） | ✅ **Bases**（核心插件，1.9.10+） |
| **折叠问答（猜 → 展开）** | ✅ **折叠 callout** —— 官方原文：加 `+` 或 `-` 在类型标识之后；`-` 让它**默认折叠**。写法 `> [!faq]- 问题` |
| 概念图 | ✅ **Canvas**（核心） |
| 跳转 / 嵌入 | ✅ block reference `^id`、embed `![[ ]]` |
| 属性 / 元数据 | ✅ **Properties**（核心） |

**唯一真正需要插件的是 Spaced Repetition**（`::` 卡 + `==cloze==`）——
**而它恰好就是作者自己也没装的那个**（实测 `~/.obsidian/plugins/` 里没有）。
**这反过来证明：不该依赖它。**

→ **结论：这个项目做到「只写 Markdown、不依赖任何社区插件」这一层。**
理由不是保守 —— 是**原生能力从 2025-08 起已经够了**。落空的只有 `::` 卡片式间隔重复，
而那是**可选增强，不是地基**。

### 7.2 导入接口：**约定一个目录 + 一条命令**

同类产品（Notion / 通义听悟 / 飞书妙记）**全是云上传**，而本项目是 local-first
（音频不出机器），走云上传自相矛盾 —— **这里没有可直接抄的先例**。
唯一相近的是 CLI 生态：`simonw/llm embed-multi <目录>` —— **指一个目录，它自己索引**。

**推荐形态**（复用已存在的路径，不引入新概念）：

```
<vault>/Study/<课号>/materials/     ← 朋友把 PDF / PPTX / DOCX 丢进来
cl materials                         ← 一条命令：转 markdown + 落到约定位置
```

`Study/<课号>/materials/` **是作者 vault 里已经在用的路径**，不新造概念。

### 7.3 转换工具：选 **Docling**（IBM）

| 工具 | 纯 CPU | 许可 | 判断 |
|---|---|---|---|
| **Docling** | ✅ **明确支持离线 / air-gap** | **MIT** | ✅ **选它** —— 与 ClassLive 同为 MIT，小 VLM（258M），LangChain/LlamaIndex 官方集成 |
| markitdown（微软） | ✅ | MIT | 最轻，**但它的 OCR 插件是调 LLM vision API** —— 扫描件必须上云 |
| MinerU | ✅ | ⚠️ **AGPL-3.0** | 分数最高，**但 AGPL 对一个 MIT 项目是法律问题**，且要 16GB+ 内存 / 20GB+ 存储 |
| Marker | ⚠️ | GPL 系 | 学术论文准确率最高（96.67%），**但要 4GB VRAM** |
| unstructured | ✅ 仅 `fast` | Apache | `fast` = pdfminer 规则，**扫不了扫描件、多栏常错** |

**⚠️ 代价（必须认账）**：Docling 要装（~258M 模型 + 依赖）→
**进 `requirements.txt` 并在 README 说清**。对朋友是又多一个安装步骤。

### 7.4 分发方式：**不附带 `.obsidian/`**

社区确实有人这么做（`jmiba/Obsidian-Vault-Template` 等，插件也一起打包），
**但风险是**：朋友**当成自己已有的 vault 打开**时会**覆盖他的设置**。

→ **ClassLive 只写笔记，绝不碰 `.obsidian/`。** 这也与"不擅自改用户环境"同源。

### 7.5 阶段的划分

| 阶段 | 做什么 | 依赖 |
|---|---|---|
| **7-A** | 文档：把 `Study/` 的结构约定写下来 + 发一个 `materials.example/`（照 `glossary.example.txt` 的先例） | 无 |
| **7-B** | `cl materials` 子命令：Docling 转换 → 落到 `Study/<课号>/materials/` | Docling 进 requirements |
| **7-C** | 笔记生成时读 materials（§6 的 L1 / L2） | 7-A 或 7-B |

**先做 7-A** —— 零依赖，而且**没有它，7-B/7-C 都是空中楼阁**（朋友不知道目录该长什么样）。

### 7.6 验证清单

- [ ] 一个**全新的空 vault** 跑完 `cl` 能正常出笔记（`mkdir(parents=True)` 已确认自动建目录）
- [ ] 不装任何社区插件时，生成的笔记**所有交互仍可用**（折叠 callout、Canvas、锚点）
- [ ] `cl materials` 对**扫描版 PDF** 与**文字层 PDF** 都能出 markdown
- [ ] 转换失败**不阻塞**笔记落盘（素材是增强，不是前置）
- [ ] 全流程**不写 `.obsidian/`**（用 `git status` / `ls -la` 验证）

### 7.7 反模式护栏

- ❌ **别要求朋友装社区插件** —— 原生能力够（§7.1），加门槛只会变成"装了不用"
- ❌ **别附带 `.obsidian/`** —— 会覆盖朋友的设置
- ❌ **别选 AGPL 的转换器**（MinerU）—— 与 MIT 许可冲突
- ❌ **别让素材转换阻塞上课或笔记落盘** —— 它只是增强
- ❌ 别在 README 里写"可被 Spaced Repetition 插件识别"却不说明**要自己装**
  （现在 `Lectures/` 的笔记里就有这句，而作者自己都没装 —— **空头支票**）

## 8. Jev 模型：❌ 不做（第 5 次复核，2026-09-25）

| 检查 | 结果 |
|---|---|
| 项目里 100% 的模型调用 | **都是生成文本** —— Jev 生成不了 |

**翻转条件**：出现**高频重复、答案空间可穷举、且没有确定性替代**的判断时才值。目前没有。
