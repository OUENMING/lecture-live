# 计划：入口面板瘦身 + 一键更新（不开终端）

> 2026-10-02 · **只是计划，没有改任何仓库代码**。以 HEAD（`03b7625` 之后）的代码为准，
> 符号不写行号。加载的 skill：`codebase-design`（缝的位置）· `impeccable`（Operate 模式：
> 「earned familiarity / consistency over surprise」—— 沿用面板既有视觉词汇，不发明新控件）。
> 对应手册 §10 两条账：「入口面板太大」+「卡片一键更新（重建 + 自动重开）」。**两件事互相牵制，所以合并成一份。**

## 0. 一页纸

**先说三个读代码得出的、会改变方案的发现：**

1. ⭐ **「每次都要终端」的根因不是"重建必须"，是指纹里有 `VERSION`。**
   `make-app.sh` 的构建指纹 = `make-app.sh` + `tools/make_icon.py` + `VERSION`。
   而 `VERSION` 烤进 `.app` 的**只有 Info.plist 的 `CFBundleShortVersionString`**
   （全仓 `.py` 里没有任何代码读它 —— 已 grep）。所以**每发一版就"过期"一次，
   而这次重建对运行时没有任何作用**。把 `VERSION` 移出指纹 → 只有 `make-app.sh` / 图标真改了才重建。
   ⚠️ 但 `make-app.sh` 本身近期改得很勤（`git log`：9/26、9/29、10/1 ×3），
   所以这一步**治大多数发版、治不了全部** → 仍需要守护小流程兜底。
2. ⭐ **面板大的真凶不是落点条，是卡片。** 每张卡 88pt（标题行 + 准备度行 + **单独一行按钮**），
   几门课就乘几。落点条只占一次 96pt。把按钮并进标题行：卡 88 → 56。
3. ⭐ **面板高度公式用的是 `mainScreen().frame()`（整屏 982），不是 `visibleFrame()`（871，扣掉菜单栏和 Dock）。**
   所以那条「卡片区最多占屏幕 60%」在你这台机器上按的是**多算了 111pt 的屏**。

**结果（按代码公式算，非截图实测）：**

| | 现在 | 瘦身后 | 再加更新入口 |
|---|---|---|---|
| 1 门课 | ≈ 362 | ≈ 330 | ≈ 330（更新是就绪条里的一格，**零额外高度**） |
| 5 门课 | ≈ 756 | **≈ 572** | ≈ 572 |
| 7 门课 | ≈ 863（顶满 871） | **≈ 705** | ≈ 705 |

**更新入口 = 就绪条里条件出现的第 5 格**（有更新才出现），**不是新卡片**。

## 1. 现状核实（全部现查）

### 1.1 面板高度怎么来的（`entry_panel._build`，**从下往上推**）

```
h = PAD(20)+FOOT_H(46) + DROP_GAP(8) + DROP_H(96) + DROP_GAP(8)
    + body_h + 8 + READY_H(40)+READY_GAP(10) + TITLE_H(34) + PAD(20)
body_h = min(n*(card_h+CARD_GAP10.5) - 10.5, 屏高*0.60)      ← body_height()
card_h = card_height(entry) = 10 + 18 + 16+2 + 10 + [8 + 24 按钮行] + [结果列表…]   = 88
```
固定开销（卡片区之外）≈ 276pt。`WIDTH = 680` 固定。

### 1.2 落点条（`DROP_H = 96`）是**四种模式共用的同一块地**

提示（3 行文字 + 3 颗控件）↔ 新增课程输入行（`ADD_ROW_Y=47`、`ADD_REPLY_Y=24`）↔ 批量归档按钮 ↔ 搜索「清除」。
全部用 `DROP_H` 派生 y。⚠️ **所以瘦身不是改一个常数** —— 输入行 + 反馈行要在更矮的框里重排
（47+24 → 约 27+7，仍不重叠：反馈行顶 24 < 输入行底 27）。`HINT_W` 的余量只剩 29.7pt（源码注释写明），
再动控件会让提示折行并被静默吃掉第二行。

### 1.3 卡片按钮行（`_make_card`）

`[开始上课 92｜148(预选时)] [不是这门？84(仅预选)] [课次 68]`，锚在卡底。
合并进标题行后，**最坏一张（预选卡）按钮区 ≈ 148+8+84+8+68 = 316pt**，
卡内宽 640−20 = 620 → 文字区只剩 ≈ 300pt。标题 `card_title` 与准备度行
（`7 份课件 · 73 条术语 · 上次上课 9/25`）都要 `truncate`。⚠️ 这是瘦身最大的视觉风险。

### 1.4 就绪条（`make_ready_strip`）

四项各自是无边框按钮，宽度按 `sizeToFit()` 的实测文字。**我现场量了 16 种状态文案**：
单项 83–109pt。四项最坏 ≈ 512pt（含 12 内边距 + 16 间距），可用 616pt →
**第 5 项只剩 ≈ 100pt**。所以更新项文案必须 ≤ 90pt（见 §4），且 **只在有更新时才出现**（常态零占用）。
⚠️ `ready.dismissed()` 会整条隐藏就绪条，但 `entry_panel` 里**没有任何调用点写它**
（`ready.dismiss` 只有定义）→ 今天走不到；**更新项不能依赖它**，写判据钉住。

### 1.5 更新链路今天的样子

| 环节 | 现状 |
|---|---|
| 谁出「本次更新」卡片 | `main._whatsnew_payload()` → **录课进程的悬浮窗**（`overlay.show`）。**入口面板（`entry_launch`，短命独立进程）里没有任何更新入口** |
| 卡片「立即更新」 | `overlay._whatsnew_update`：进程内 `update.pull()` + 经确认的 `deps`；**`app` 步被摘出**（F1：`make-app.sh` ③ 会杀掉正在跑的自己），只引导"去终端 `cl update`" |
| 后台自动更新 | `update.spawn_auto_update()`（退出时脱离进程）；默认 manual（只有 CHANGELOG 明写 `auto` 才自动） |
| `.app` 重建 | `update.run_step("app")` ← `_app_stale_reason()` ← `make-app.sh --up-to-date`（出错倒向"重建"，故意的） |
| `make-app.sh` ③ | 按路径尾部 `ClassLive.app/Contents/MacOS/python` 找实例；**排除调用方进程树**；`main.py` 实例（可能在录课）→ **拒绝并问人**；`instance_lock.probe()` 探锁（带看门狗） |
| 启动链 | 双击 → `.app` 的 `sitecustomize` → `cl` → **`entry_launch.py`（独立短进程，退出码 0/1/2/3/4 是与 `cl` 的契约）** → `exec main.py` |

## 2. 设计

### 2.1 缝与模块（codebase-design）

**现有的缝，沿用**：`update.pull()` / `update.pending_steps()` / `update.run_step()` 三个入口不动；
`make-app.sh` 仍是**唯一的重建实现** 和 **指纹唯一定义点**。

**新增两处，各自两个适配器才算真缝：**

| 新模块/函数 | 接口（调用方要知道的全部） | 两个适配器 |
|---|---|---|
| `update.spawn_rebuild(*, log=None) -> bool` | 「**把重建交给一个脱离本进程的守护脚本**」。返回是否成功启动；**不等待、不抛** | 真：`Popen([守护脚本], start_new_session=True)` ／ 测：注入假 `popen` 记录参数 |
| `scripts/relaunch-after-update.sh`（**系统 bash**，不依赖 `.app` 里的 python） | 等**无** `ClassLive.app/Contents/MacOS/python` 进程 → 跑 `make-app.sh` → `open ClassLive.app` → 写结果文件 + 发系统通知 | 真：真 `make-app.sh` ／ 测：f1 假世界里的假 `make-app.sh`（3.8.7 已有这套夹具） |
| `ready.update_item(state) -> dict \| None` | 纯函数：`state` → 就绪条那一格（`None` = 不显示）。⚠️ **永远不返回 `todo`**（同 `engine_item` 纪律：可选项不挡上课） | 无缝（纯函数） |

**删除测试**：删掉 `spawn_rebuild` → "为什么必须脱离进程 / 为什么用系统 bash / 为什么不杀自己" 的复杂度
散回 `overlay` + `entry_panel` 两处各写一份 → 它在挣钱。

### 2.2 更新入口放哪、长什么样（impeccable · Operate）

**判据是 earned familiarity**：就绪条本来就是「这台机器能不能上课」的状态栏，每一格 = 一个词 + 一个状态词，
点它就地修。更新是**同一类东西**（"这台机器的 ClassLive 是不是最新"）→ **做成第 5 格，不发明新控件**。

| 状态 | 显示（≤ 90pt，实测 `↑  更新  有新版本` = 94.4pt，需再压） | 点击 |
|---|---|---|
| 没查到 / 没更新 / 在录课（`on_start is None`） | **不显示** | — |
| 有更新（`behind>0`） | `↑  更新  3.8.8` | 确认框 → 拉代码 +（经确认的）补依赖 → 需要重建则交给守护脚本并退出面板 |
| 代码已最新但 `.app` 过期（`_app_stale_reason()` 非空） | `↑  更新  需重开` | 同上，只做重建 |
| 进行中 | `◌  更新  进行中…`（不可点） | — |
| 上次自动重建失败（读结果文件，一次性） | `⚠  更新  上次没成`（点 → 状态行说原因 + 终端命令） | — |

⚠️ **文案要先给你过目**（仓库规矩）：上表是草案，不是定稿。
⚠️ **在录课时不出现**：沿用 `on_start is None` 这条既有约定（"能兑现才给，不给就不画"）。
⚠️ **不做进度条**（就绪条那条 HIG 引用：只画状态，不画假进度）。重建 1–3 分钟里**面板已退出**，
进度靠系统通知（见 §2.4）。

### 2.3 为什么是「面板退出 + 守护脚本」而不是「面板里直接重建」

重建会整个替换 `ClassLive.app/Contents/`，而面板进程**就跑在里面**。F1 已经证明在进程内跑
`make-app.sh` 会杀掉自己。→ 守护脚本必须：
- **住在 `.app` 之外**（仓库的 `scripts/`），**用系统 bash**（不是 `.app` 里的 python —— 那个正是要被换掉的东西）；
- 用 `start_new_session=True` 起，父进程退出后它继续（同 `spawn_auto_update` 的既有先例）；
- 命令行里**不出现** `ClassLive.app/Contents/MacOS/python`（否则 `make-app.sh` ③ 的 pgrep 会把它自己当实例）。

**退出码契约**：`entry_launch` 新增 `5 = 已交给更新守护（不录课、不重开面板）`；`cl` 的 `case` 加一行
`5) echo "（正在更新，完成后自动重开）"; exit 0`。⚠️ 与 1/4 同类：**不录**，因为 `.app` 马上要被替换。

### 2.4 重建期间用户看见什么

`.app` 是 accessory（无 Dock 图标），重建 1–3 分钟里**屏幕上什么都没有** → 看起来像闪退。
→ 守护脚本用 **`osascript -e 'display notification …'`** 发两条系统通知：
开始（"ClassLive 正在更新，完成后会自动重开"）· 结束（"更新完成"/"更新没成功 —— 已恢复旧版"）。
⚠️ 这是**发通知，不是改系统设置**；若通知被用户关了，就只剩结束后的自动重开 + 结果文件，不重试、不去碰设置。

### 2.5 失败怎么办（对着 `make-app.sh` 已有的恢复机制）

`make-app.sh` ③ 已有 trap：构建中途失败 → **把旧 `.app` 移回来**。守护脚本在它失败时：
① 仍 `open` 旧 `.app`（用户不会丢掉一个能用的 app）② 写 `~/Library/Logs/ClassLive/rebuild-result.json`
`{"ok":false,"at":…,"why":"最后一行错误"}` ③ 发通知。下次面板打开读这份文件，**一次性**显示在更新格上，
读完即删（同 `.update-notice` 的一次性语义）。

### 2.6 守护脚本**不做**的事

- ❌ 不杀任何进程。等不到 app 退出（超时，默认 10 分钟 —— 收尾精修实测最长 11 分钟）就**放弃重建**并通知，绝不强杀。
  （入口面板那条路几乎不会等：面板进程本来就是短命的。超时主要防"用户在面板退出后又手动启动了一个并开始录课"。）
- ❌ 不跑 `git`。拉代码已经在面板进程里做完了；守护脚本只重建 + 重开。
- ❌ 不装依赖（依赖是 `deps` 步骤，用户确认后在面板进程里装进 `.app` 的 python —— 重建**之前**）。

### 阶段 P1 · 面板瘦身

**P1-a 卡片：按钮并进标题行（88 → 56）** —— 最大收益，也最大风险

- `card_height()`：无结果时 `h = CARD_PAD + L1_H + L2_H + 2 + CARD_PAD`（= 56），**去掉** `CARD_GAP_V + BTN_H`
  那一项（按钮不再占独立行）。有结果列表时仍累加 `RESULT_LEAD + n*RESULT_ROW`。
- `_make_card()`：按钮改为**右对齐、垂直居中于标题两行**；`inner_w` 文字区 = 卡内宽 − 按钮区宽 − 间距；
  标题与准备度行都 `truncate=True`（`panel.make_label` 已支持）。
- **预选卡的按钮压缩**：`开始上课 · 就是这门`(148) → 保留文案但**用 primary 样式**，`不是这门？`(84)
  → 先保留（它是 HAX G8/G9 的纠错入口，不能删）。最坏按钮区 316pt；若标题被截得太狠，
  **回退方案**：预选卡保持两行布局（只有 1 张卡高 88，其余 56）。——**判据：按课程名最长的真实数据量一次**，不拍。
- ⚠️ `card_height` 与 `_make_card` 的 y 必须**同一组常数**（文件里反复记的纪律）。
  真正的锁在 `tests/test_panel.py`「建出卡片、断言没有子视图超出 `card_height(entry)`」——
  **改完先让它在夹具里真的有内容再跑**（它自己写明夹具要真有内容才兜得住）。

**P1-b 落点条 96 → 56**

- `DROP_H = 56`；提示 3 行 → **2 行**（标题 15pt + 一行 11pt）。
  ⚠️ **文案要先给你过目**：现在三行是「把课件全拖到这里 / PDF·PPTX·DOCX·课表 .ics·文件夹也行 /
  自动认出哪份属于哪门课 —— 认不出的会让你核对」。提案：合并后两行为
  「PDF / PPTX / DOCX · 课表 .ics · 文件夹也行 —— 自动分到各课」；
  "认不出的会让你核对" 挪进拖入后的批量确认卡（那里本来就会让核对）。
- `ADD_ROW_Y 47 → 27`、`ADD_REPLY_Y 24 → 7`（按 `DROP_H` 派生，不各写一遍）；
  批量/搜索/新增三处按钮的 `(DROP_H - BTN_H)/2` 自动跟随。
- `HINT_W` 仍由三颗控件宽度推出；⚠️ 文案缩短后余量更大，但**不要借机再塞第 4 颗控件**。
- 判据：`tests/test_entry_panel.py` 里量文字宽度 vs `HINT_W` 的那条（第 858 行一带）**重量一次**。

**P1-c 高度公式改用可视区**

- `body_height(n, screen_h, card_h)` 调用点：`NSScreen.mainScreen().frame()` → `visibleFrame()`。
- 新增**总高上限**：整面板 ≤ `visibleFrame.height × 0.92`（今天只限卡片区 60%，固定开销 276 在外面，
  小屏上会超）。超了就压缩卡片区（`body_h = cap − 固定开销`，最小一张卡）。
- 判据（纯函数）：`panel_height(n, visible_h)` 在 visible_h ∈ {600, 700, 871, 1200} × n ∈ {0,1,5,7,30}
  下**永不超过 visible_h×0.92**，且卡片区 ≥ 一张卡。**变异验证**：把 `visibleFrame` 改回 `frame` 会红。

**P1-d（暂不做）缩放**：手册评估过——高度可做、宽度不建议。P1-a/b/c 做完后再量一次：
若 7 门课仍 >0.92 屏就加（Titled + 隐藏红绿灯，`overlay` 有先例）；否则**不做**，别为没问题的东西加复杂度。

## 5. 风险（诚实标注哪些我没验证）

1. ⚠️⚠️ **麦克风授权会不会因为重建 `.app` 而被 macOS 重新询问——我没测过。** 这是最大的未知。
   `make-app.sh` 每次重建都生成新的可执行文件副本，TCC 按什么匹配（bundle id / 代码签名 / 路径）取决于签名状态，
   我没在你机器上验证，**也不会为了验证去动你的系统设置**。→ 真机验证清单第 1 条，你在场时做。
2. ⚠️ 卡片单行化后的**真实视觉效果我没拍图**（避免显示器睡着拍黑图，且这一步要改完才有东西可拍）。
   P1 完成后用 `scripts/probe_entry_panel.py`（隔离模式）**改前改后各拍一张**对比
   （[[ui-criteria-two-blind-spots]]：「看得见吗」离线断言不了）。
3. ⚠️ 面板高度表是**按公式算的**，不是量的；P1 完成后用同一公式的纯函数判据 + 真机拍图双重确认。
4. ⚠️ `peek()` 的 `git fetch` 在入口面板里是**新增的联网动作**（以前面板打开不联网）。
   所以必须：后台线程 + 静默降级 + `CLASSLIVE_NO_UPDATE_CHECK` 环境变量尊重 + 不写任何状态文件。
