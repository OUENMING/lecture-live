## 0. 一页结论

**目标形态**：用户打开网址 → 允许麦克风 → 输一次通行码 → 出双语字幕（含术语注入）→ 下课后笔记出现在同一页面。不装任何东西。桌面版与网页版两条线并行。

**「先重构再上云」这个顺序对不对**：方向对，要改两处。

1. **重构的范围以「网页版要复用的部分」为界**，不是把现有代码全理一遍。要复用的是实时核心（封口、字幕排版、草稿判据、提示词拼装）和笔记流水线；`overlay.py` / `entry_panel.py` / `transcript_view.py` 等约 1.8 万行 AppKit 界面网页版一行都用不上，**不重构**。依据：D2、D3。
2. **重构之前先做 4 个穿刺**（3–4 天，一次性代码）。其中「Python 核心能不能原样跑在浏览器里」直接决定重构往哪个方向拆：能，重构的产物就是网页版的核心，一份代码两处用；不能，就要另写一份 TS，重构目标随之变成「把规则钉成两边共用的判据」。不先试就重构，是在不知道终点的情况下修路。

**三条贯穿全程的线**：

- **切片**：每一步都小到能单独合并、单独回退；每一片合并后桌面版照常能上课。不开「重构大分支」。
- **判据先行**：动任何一块之前，先有能红的判据（录制回放）；判据写完做变异验证。
- **上课链路里不放自己的机器**：浏览器直连 Soniox，翻译走现有 Worker。VPS 只跑下课后的笔记，挂了只是笔记晚到。

**重构本身用户看不见。** 能让桌面版用户感觉到变化的，是搭在重构上的几件具体的事：字幕不再偶发整窗停住、启动不再偶尔等五六秒、内存降下来、失败不再静默。这些单列为 U 线（§5），每件都有改前的数字，改后用同一个报告字段复量。

## 1. 要什么，不要什么

**要（网页版第一版）**：麦克风实时转录 · 逐句翻译 · 课程术语注入（识别端 + 翻译端）· 逐句落盘不丢 · 置顶字幕小窗 · 课件上传生成术语表 · 下课自动出笔记、网页内查看与下载。

**后续再加**：网课音源（抓标签页 / 系统声）· 实时总结 · ❓ 标记与点拨 · 讲解问答 · 手机适配 · Safari / Firefox。

**第一版的浏览器范围**（Q9）：桌面 Chrome / Edge。其他浏览器打开时，开课页直接说明「请换 Chrome 或 Edge」，不让人走到一半才报错（E5）。

**不做（明确放弃，别再反复讨论）**：

| 不做 | 为什么 |
|---|---|
| 把桌面版的功能全搬到网页（功能对等） | 被点名的反模式（D2）；桌面版自己留着这些功能 |
| 网页版的本地模型 / 离线模式 | 浏览器里跑不动同档模型；需要离线的人用桌面版 |
| 重构 AppKit 界面层 | 网页版用不上；桌面版界面当前能用 |
| 把现有模块搬进 `src/` 或子包 | `HANDBOOK.md` 仓库布局一节 2026-10-01 定的：扁平、别动。边界改用 `check.py` 规则守（见 P0） |
| 一次性大改写（另起一个新仓库重写） | 判据文化、事故教训、提示词冻结都在现仓库里 |
| 原生 Windows 客户端（Owen：先放，以后再说） | 网页版在 Windows 的 Chrome / Edge 上直接可用，且能抓整机声音（A5）。重构时顺手做的准备只有一条：平台调用只许出现在适配器模块里（P0 的纯度规则管着） |

## 2. 这份计划特有的约束

通用硬规矩在 `HANDBOOK.md` §3 与 `CLAUDE.md`「本仓库特有雷区」，这里只列和本计划直接相撞的：

- **推到 `main` 就是发给用户**：更新是用户机器上 `git pull` 上游分支，默认自动。重构切片可以合进本地 `main`，**推送仍按发版规矩走**（作者点头、攒批）。
- **仓库是公开的**：服务器地址、通行码、朋友的课堂数据不进仓库、不进本文。
- **朋友的转录不进测试夹具**：回放用的磁带只录作者自己的课。
- **花钱的实验一律 test key**；笔记判据用 `scripts/notes_bench.py`（自带 HOME 隔离）。
- **提示词是冻结的**：`tests/test_translator.py` 逐字钉着云端提示词布局。搬动提示词拼装代码时**只搬不改**，前缀缓存靠它。
- **子代理不跑 `main.py` / `cl`**（hook 拦着）：回放判据必须是进程内调用 + HOME 隔离的测试。

## 3. 目标架构

```
浏览器（静态站点，自有域名）
  采音 worklet ──PCM 16k──▶ Soniox WebSocket（临时 key，直连）
        │                        │ token 流
        │                        ▼
        │              实时核心（封口 · 字幕排版 · 草稿判据 · 提示词拼装）
        │                   └ 与桌面版同一份逻辑：Pyodide 直接跑 Python，或 TS 移植（S1 定）
        │                        │ 界面状态快照（ViewState）
        │                        ▼
        │              渲染：主页面 + 置顶字幕小窗（Document PiP）
        │
        ├── 逐句写 IndexedDB（先落盘）──定时同步──▶ Worker ──▶ R2
        └── 翻译 / 草稿译文（流式）─────────────▶ Worker ──▶ DeepSeek 等

Worker（现有 asr-worker，扩展）
  通行码 · 额度 · 铸 Soniox 临时 key · LLM 代理 · 会话与任务账本（Durable Object）· R2

笔记 runner（Python，无状态，拉任务）
  跑在作者的 VPS 上（常开）
  取逐字稿 + 课件 → 现有笔记流水线 → note.html / note.md 写回 R2
  runner 上**不放任何供应商 key**，只持一枚可吊销的 runner 令牌，模型调用仍经 Worker
```

**桌面版**在同一个仓库里继续存在：重构后它也用同一个实时核心和同一个笔记服务函数，只是界面是 AppKit、存储是本地文件、笔记在本机进程里跑。

**为什么这样分**：

- 上课链路不经过自己的机器：VPS 只有 2 核 2 G，不该让一台小机器决定课能不能上。浏览器直连是 Soniox 的官方做法（B1），Worker 现在就在铸临时 key。
- 笔记流水线不重写：它是纯 Python + httpx，峰值内存 145 MB（底稿 §2），VPS 够跑。搬到 Python Worker 不行：没有线程、128 MB 上限（C4）。
- runner 用「拉」不用「推」：VPS 重启或断网期间任务留在账本里，回来接着干；将来要加第二台机器不用改架构。任务账本放 Durable Object 而不是 Cloudflare Queues —— 免费档队列消息只留 24 小时（C3），runner 停一天任务就没了。
- 网页本身是纯静态文件，放 Cloudflare Workers 的静态资源（官方对新项目的建议，静态请求免费不限量，C9），绑 bldcam.page 的子域。不走 `*.workers.dev` / `*.pages.dev`（大陆不可达，C8）。
- 不用 InstaBox（Owen 11-14：VPS 放得下就不用）。实测笔记流水线峰值 145 MB，VPS 可用 820 MB（底稿 §2）。整课峰值由 S4 补量；放不下的处理见 §6。

### P0 · 安全网（3–5 天）

目的：让后面每一刀都有东西会红。

1. **录制回放判据**。在 `tests/` 里做一个进程内回放：给 `main.run()` 打四个桩 —— 静音音源、假的 `StreamASR`（按磁带吐消息）、假的翻译器（按磁带回译文）、记录型 UI（把每次 `ui.*` 调用记成一行），HOME 与写端全隔离。磁带从作者自己的一节真课录（需要给桌面端加一个默认关闭的原始消息录制开关，登记进 `HANDBOOK.md` §6.1）。
2. **比什么**：定稿句的序列与内容、`sessions/*.md` 落盘内容（去掉时间戳）、每句译文。**不比**草稿的交错顺序（线程调度决定，本来就不稳定）。
3. **变异验证**：故意丢一句、故意把两句的译文对调、故意漏写一行 `.md`，三种都必须红。
4. **给 19 个读源码文本的测试建清单**：哪些钉的是行为（留），哪些钉的是「这段代码在这个文件里」（搬家时同步改）。清单放进测试文件头。
5. **`check.py` 加纯度规则**：一份 `CORE_MODULES` 清单，清单里的模块不得 import AppKit / objc / threading / httpx / sounddevice / `paths`。起步清单 = 底稿 §1 里已经纯的那几个。

完成判据：回放在未改动的 `main` 上连跑 5 次全绿；三种变异各自变红；`check.py` 全绿且新规则在故意违规时变红。

### P1 · 契约（约 1 周）

目的：把隐式约定变成写在类型里的约定。全是机械改动，行为不变。

1. **事件类型**：`streamq` / `drafts` / `drafts_zh` 的位置元组换成 frozen dataclass（`Final`、`StreamDelta`、`Endpoint`、`Notice`…）。一次只换一种 tag，换完回放必须逐字相同。`drain()` 的分发改成对类型穷尽匹配，R28 那条「漏加分支」的告警随之变成「类型检查过不了」。
2. **UI 端口**：`ui_port.py` 里一个 `typing.Protocol` + 一个全空实现的基类；`Overlay` 与 `TerminalUI` 继承它。删掉 40 处 `getattr(ui, …)` 守卫。R17（签名漏一层就全崩）由协议一致性检查接管。
3. **界面状态快照**：定义可序列化的 `ViewState`（当前屏上哪几行、每行的英文 / 中文 / 身份、状态点、提示条），由同一批事件投影出来。桌面版先以**影子模式**并行算它、不拿它画界面；回放里核对「按 ViewState 渲染出的文本」与记录型 UI 收到的调用一致。这一步就是在网页版出生之前验它的数据契约。

完成判据：回放逐字相同；`getattr(ui` 在 `main.py` 里计数为 0；`item[` 下标读计数为 0；影子 ViewState 与实际 UI 调用在回放磁带上零差异。
闸门 G1：以上全过 + 作者用它上 2 节真课无异常。

### P4 · 服务端（1–2 周）

1. **Worker**（沿用「纯逻辑不 import `cloudflare:*`、Node 测试直接跑」的现有写法）：
   - CORS：只放行网页版那一个来源，不用 `*`（E6）。
   - 会话端点：开课、追加逐句、下课。追加要幂等（带序号）。
   - 任务账本：Durable Object 里一张表，状态 `待做 / 进行中 / 完成 / 失败`，带租约到期时间与心跳。
   - runner 端点：领任务、续租、交结果；runner 令牌与用户通行码是两套。
   - 网页端防刷（E7）：每码日 token 上限与实时转写日秒数上限给默认值；`max_tokens` 封顶；浏览器设备单独计数。
   - R2 目录按通行码的哈希分前缀；生命周期规则 30 天（Q2），并提供「立即删除我的数据」。
2. **runner**：拉任务 → 续租心跳 → 调 P3 的服务函数 → 写回。同一任务重复领取不产生第二份笔记。VPS 上用 systemd 常驻，并发先限 1，带内存上限。
3. **Soniox 临时 key**：确认铸出来的是 `snx_temp_` 格式（B2）；给浏览器的 key 设 `single_use` 与会话时长上限。

完成判据：Node 测试覆盖账本状态机（含租约过期被另一台领走、重复交结果）；runner 在「跑到一半被杀」「网络断 2 分钟」「同一任务被领两次」三种情况下各有判据；用 test key 从一份真实逐字稿走完「下课 → 笔记写进 R2」。
闸门 G4：以上 + VPS 上连跑 5 节真实逐字稿的笔记，记下每节耗时与峰值内存。

#### 界面方案（Owen：高级感、优雅、克制，但功能不能少）

**基调**：暗字幕 + 亮笔记。上课界面沿用桌面版的深色磨砂，浮在课件上也看得清；课后笔记用暖白纸面，像排版讲究的文档。两个面共用一套字体、间距、圆角和动效曲线。

**技术**（Q6b，Owen 11-14 提出、评估后采纳）：SvelteKit（`adapter-static`，产物纯静态）+ Svelte 5 runes + TypeScript + Tailwind v4 + shadcn-svelte（底座 Bits UI），开发时接 Svelte 官方 MCP。

为什么它比我原先建议的 React 那套更合适：

- **这个产品的核心画面是一条高频变化的文字流**（草稿每秒改好几次）。Svelte 5 按「哪个值变了就只改哪个文字节点」更新，没有整棵组件重算再比对这一步；公开基准里它的体积约是 React 的五分之一、首次绘制快约 3 倍、内存少约三分之一（F3）。落到用户身上应该是：页面一打开就有东西、字幕不掉帧 —— 这是预期，不是测量；S3 和 M1 的完成判据里各有一条「回放 10 分钟、超过 50 ms 的长任务为 0」来验。
- **我原先选 React 的主要理由是「写代码的模型对它更熟」，这条被官方 MCP 抵掉了大半**：它给模型喂最新文档，并用 `svelte-autofixer` 静态检查模型写出的代码，循环到没问题为止；OpenCode、Claude Code、Codex、Pi 都有官方插件（F9）。
- runes 可以写在普通 `.svelte.ts` 模块里 —— 界面状态快照（ViewState）做成一个响应式对象，主页面和置顶小窗共用，不用另配状态库。
- shadcn-svelte 和 shadcn/ui 是同一种做法（源码拷进仓库、归自己改），已是 Svelte 5 原生写法，更新很勤，2026-10 还加了「跟随流式输出、加载历史不跳动」的滚动组件（F10），正好是逐字稿区要的。

代价与对策（要认的）：

| 代价 | 对策 |
|---|---|
| 生态比 React 小一个数量级（npm 周下载约 610 万对 1.75 亿，F13），现成的第三方件少 | 第一版用到的第三方件很少（BudouX、pdf.js、Pyodide 都与框架无关）；Soniox 走原生 WebSocket，不依赖它的 React SDK |
| shadcn-svelte 是社区移植，跟上游有时差（F10） | 组件源码在自己仓库里，缺什么自己补；只取用得上的组件 |
| 弱一些的模型会写出 Svelte 4 的老写法（`on:click`、`export let`、store） | 任务单硬性要求：每个 `.svelte` 文件过 `svelte-autofixer` 到零问题；`svelte-check` 进完成判据 |
| SvelteKit 3 是当前主线，但 shadcn-svelte 10 月上旬还挂着 Kit 3 的 issue（F11） | 搭脚手架当天复核 #2915：已修就用 Kit 3，没修就用 Kit 2 最新版，以后用 `npx sv migrate` 升 |
| 不用实验特性 | Svelte 的 async 模式、SvelteKit 的 remote functions 目前都是 experimental，第一版不开 |

SvelteKit 只当「路由 + 构建」用：`ssr = false`，开课页和说明页预渲染（官方对纯 SPA 的提醒，F12），没有任何服务端代码 —— 接口全在现有 Worker 上。

回退条件：S3 穿刺用 Svelte 写，顺带验证「组件挂进置顶小窗」（F14 是读源码推断）。挂不进去或事件收不到且一天内绕不过 → 改回 React 19 + shadcn/ui，其余计划不变。

**怎么做出高级感**（依据 F4–F6，不是口味）：

- 高级感来自「每个看得见的地方都有人做过决定」，不来自某种风格。所以**不沿用组件库的默认主题**：自定中性色（偏暖，不用默认的 slate / zinc）、一个圆角档位、一组字体搭配、**只用一个强调色**、外加一个自己的招牌 token（磨砂面板的配方，沿用桌面版 `panel.py` 那一份）。
- 设计 token 只有一个出处，桌面版与网页版共用（`PLAN-3.11-20261103.md` 已经计划了 `uitokens`）。
- 每个控件做全六种状态：悬停、聚焦、按下、禁用、加载、空。聚焦环自己设计，加载用和版面一致的骨架，不用转圈。
- 动效：交互 ≤ 200 ms；只动 `transform` 与 `opacity`；不写 `transition: all`；尊重「减少动态效果」。CSS 优先（过渡、`@starting-style`、`linear()` 弹簧、同文档 View Transitions），不够再上动效库。
- 字幕文字要稳：已经显示的字不重排，只在句尾生长（同类项目踩过的坑，E8；桌面版的依据在 `RESEARCH-live-caption-rollup.md`）。

**中英混排**（桌面版已经讲究的，网页版要对齐）：

- 字体走系统栈（macOS 苹方、Windows 微软雅黑 / Noto），不加载中文网络字体。
- 数字用等宽数字（`font-variant-numeric: tabular-nums`）。
- 中文标点挤压（`text-spacing-trim`）只有 Chromium 支持，中英自动间距（`text-autospace`）各家支持说法不一（F7）—— 两个都当锦上添花，不依赖。
- 中文断行用 BudouX 的 JS 版，和桌面版 `vendor/budoux` 是同一套模型。

**页面清单**（功能不少的落点）：开课页（课程卡片、准备度、课件上传）· 上课页（字幕、状态点、术语、模式切换）· 置顶字幕小窗 · 课后页（笔记阅读、逐字稿、下载）· 设置（通行码、设备、删除我的数据）。

**流程**：先用设计类 skill 定方向、出静态稿给 Owen 看；Owen 点头后再写组件；写完用审查类 skill 过一遍。

完成判据（第一版 = M1–M6）：作者用网页版完整上一节真课，逐字稿句数与同时开着的桌面版相差 ≤ 2%；中途刷新页面不丢已定稿的句子；笔记在下课后 15 分钟内出现；Windows 的 Chrome 上重复一遍。
闸门 G5：以上 + 一位朋友在自己的机器上零指导走通。
