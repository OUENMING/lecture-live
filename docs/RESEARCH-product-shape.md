> 作者 2026-09-26 的原话：
> 「与其这样子不如往一个完整的软件上面做？还有就是我有一个 VPS 看能不能派上用场，
> 因为这里有一个逻辑就是提取课件上的信息以及课程信息做关键词。这也是一个功能。重新考虑调研一下。」

配套阅读：`docs/RESEARCH-entry-and-export.md`（入口形态 + 导出机制那份）。
**每个数字都是本机实测，每条引文都已回源核对；核不实的引文一律不用，并在 §7 列出来。**

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 要不要做「完整软件」 | **要，但只做第 2 档**：一个 `.app` **启动器**（不含 Python，只包一个 shell 脚本）。**不要** PyInstaller 自包含打包 |
| 能不能不花 $99 就让它能双击 | **能** —— 走 `git clone` / `curl` 分发就**不会被打 quarantine 标记**，Gatekeeper 根本不启动（§3，本机实测 + Apple 官方） |
| VPS 能不能派上用场 | **不能，而且方向反了。** 课件解析这活太小、太不频繁、太不延迟敏感；而它引入的是**真实的新合规面**（§4） |
| 「课件→关键词」值不值得做 | **值得，但别新建提取器** —— `build_notes.py` 里那条 LLM 术语流水线**已经在了**，缺的只是「课件当候选词源」（§5） |
| 最大的坑 | **「喂了术语表→翻译变好」证明不了术语表内容好** —— WMT25 专门设了**随机术语**对照组（§5.2） |

## 1. 朋友今天要做什么才能用上（实测，`README.md` §安装）

```
1. git clone
2. uv venv --python 3.12 .venv
3. uv pip install 六个包
4. 下 Parakeet ASR 模型            640 MB   （huggingface_hub）
5. curl + tar Whisper 定稿模型     989 MB   ← 半个 GB 的手工 curl
6. curl silero_vad.onnx            632 KB
7. cp glossary.example.txt glossary.txt
8. cl course <课号>
   （线上课还要再装 BlackHole）
```

**模型合计 1.63 GB**（实测 `du -sh ~/models/*`：640M + 989M + 632K）。
仓库本体只有 `.git` **3.6 MB**、`.venv` **381 MB**、`sessions/` **45 MB**。

→ **重量全在「venv + 模型」，不在代码。** 这决定了下面的分档。

## 2. 「完整软件」的五个档位

| 档 | 做法 | 朋友要做什么 | 成本 |
|---|---|---|---|
| **0** | 现状：终端敲 `cl` | 上面 8 步 | 0 |
| **1** | **一条命令安装器**（`curl … \| bash`） | 粘一行 | 小 |
| **2** | ⭐ **`.app` 启动器** —— 不含 Python，只包一个 shell 脚本调现有的 `cl` | 双击 | **小** |
| **3** | 自包含 `.app`（PyInstaller 把 Python + 依赖全打进去） | 双击 | **大，且有已知硬坑**（§2.1） |
| **4** | 重写原生（Swift / Tauri） | 双击 | 巨大 |

### 2.1 为什么第 3 档是坑（PyInstaller 官方文档，逐字）

> "when launched from Finder, the app process runs in an environment with reduced set of
> environment variables. Most notably, the **`PATH` environment variable is set to only
> `/usr/bin:/bin:/usr/sbin:/sbin`**."

→ **直接打在 `cl update` 上**：它调 `uv`，而 `uv` 在 `~/.local/bin/`。Finder 启动后找不到。

> "Hidden imports can also occur when an **extension module uses the Python/C API** to do an
> import. … **There will be no warnings, only an ImportError at run-time.**"

→ **sherpa-onnx 正是 C 扩展**。同类先例：`onnxruntime` 被打包后 `DLL load failed`，
作者手工收集 DLL、写了自定义 hook **仍然失败**（microsoft/onnxruntime#25193）。

> "Starting with PyInstaller 6.0, the frozen application bundles generated by PyInstaller on
> non-Windows systems **make extensive use of symbolic links** … Failing to preserve symbolic
> links … may also lead to **run-time issues**."

→ 对 zip/dmg 分发是实际风险。同类 issue：pyinstaller#5112「Code signing and notarization
fails on macOS .app bundles」、#7533 `codesign` 报 error 109。

**对比第 2 档**：`.app` 只是个目录（`Contents/Info.plist` + `Contents/MacOS/<脚本>`），
脚本 `cd` 到安装目录、`exec .venv/bin/python main.py`。
**Python、依赖、模型全在原地不动，PyInstaller 的三个坑一个都不碰。**

## 3. ⭐ 签名与分发：不花 $99 也能双击（**本机实测**）

### 3.1 官方怎么说

- Apple Developer Program 官网逐字：*"The Apple Developer Program is **99 USD per membership year**."*
- Apple 官方：*"Beginning in macOS 10.15, **all software built after June 1, 2019, and distributed
  with Developer ID must be notarized**."*

看到这里结论像是"必须花 $99"。**但下面这条把它推翻了。**

### 3.2 ⭐ quarantine 才是开关 —— Apple 官方论坛逐字

[developer.apple.com/forums/thread/706442](https://developer.apple.com/forums/thread/706442)
（《Resolving Trusted Execution Problems》）：

> "**Unix-y networking tools, like `curl` and `scp`, don't quarantine the files they download.
> Unix-y unarchiving tools, like `tar` and `unzip`, don't propagate quarantine to the unarchived files.**"

> "If you launch a **quarantined** app, the system invokes Gatekeeper."

### 3.3 本机实测印证

```
curl 下载的文件      → 只有 com.apple.provenance，没有 com.apple.quarantine
git clone 的仓库     → 同上（cl / main.py / requirements.txt 逐个查过）
```

**→ 推论（这是本次调研最重要的一条）：**

| 分发方式 | 会不会被 Gatekeeper 拦 |
|---|---|
| `git clone`（ClassLive 现在的方式） | ❌ 不会 —— 没有 quarantine |
| `curl … \| bash` 安装器 | ❌ 不会 |
| **浏览器下载 DMG / zip** | ✅ **会** —— 浏览器自己会打 quarantine |

**所以：第 2 档的 `.app` 不需要签名、不需要 $99、不需要公证，只要继续走 git/curl 分发。**

⚠️ 反过来也成立：**一旦改成"发 DMG 让人下载"，就必须签名+公证**，否则朋友看到的是
「App is damaged and can't be opened」。**这两条路不能混。**

### 3.4 模型的业界做法

**Handy** 的 README 有专门的「Manual Model Installation (For Proxy Users or Network
Restrictions)」一节，模型放在
`~/Library/Application Support/com.pais.handy/models`，让用户自己放 `.bin` 进去
（一手：其 GitHub README）。**即模型不进包，装完再取。**

> ⚠️ 子代理引了一句「Whisper models are no longer bundled with the app」——
> **我回源抓不到那句话**，README 里没有。上面这条是**我自己核过的**。

## 4. VPS 评估：**不能，而且方向反了**

### 4.1 同类工具的自建服务器，清一色是「同步」不是「算力」

| 产品 | 服务器干什么 | 来源 |
|---|---|---|
| **Actual Budget** | *"your data lives on your devices first, with an **optional sync server you control**"*，而且那个服务器 *"**just coordinates changes between devices**"*，只要 256MB RAM / 1 核 | 一手（官方文档） |
| **Ollama** | 本地跑；云端是显式开关 | *"Ollama runs locally. We don't see your prompts or data when you run locally."* |
| **Paperless-ngx** | 有可配置的远程 OCR endpoint，但落点是 **on-prem**（你自己的实例），**不是 VPS**；且仓库有硬警告 *"should **never be run on an untrusted host**"* | 一手（discussion #12029，状态 Unanswered） |

**没有一个是"把计算卸载到自己的 VPS"。**

### 4.2 算力需求根本不够格

Docling 纯 CPU 的真实抱怨（一手 issue）：

- 100 页 PDF *"took **more than 10 minutes**"*（docling#1101）
- *"**3-4 GB RAM spike**"*（docling#2481）

→ **一份 30–50 页课件 ≈ 3–10 分钟。这是每节课一次、且课前跑完就行的批处理。**
VPS 的优势（随时在线、不占本机、弹性算力）在这个场景里**一条都不成立**。

### 4.3 而代价是真实的

- 你的 VPS **只开 2222**（实测记录）。要么加端口，要么常驻一条 SSH 隧道 —— **新增一个故障面**
- 腾讯云自己的文档定义：*"**Third Country** refers to any country outside of the scope of the
  data protection laws of the EEA…"* —— 法兰克福机器对爱尔兰用户属于这类，用它要挂 SCC
- **课件比转录更敏感**：转录是你自己听到的，课件里可能含**第三方版权内容**

### 4.4 ⚠️ 唯一形状吻合的用法，性质不同

「让朋友不用装 Docling」→ VPS 做转换服务。**但那不是"VPS 派上用场"，
是「你替朋友跑服务」—— 你从此成为数据控制者，朋友的课件落到你机器上。**
这是一个需要单独决策的产品问题，不是技术选型问题。

### 4.5 结论

**课件解析走本地 Docling，课前当离线批处理跑。关键词提取走 LLM（DeepSeek 已是现成通道）。
两个都不需要 VPS。**
VPS 继续做它现在在做的事（restic 异地备份）就好。

## 5. 「课件 → 关键词」：值得做，但**不要新建提取器**

### 5.1 ⭐ 流水线已经在了（本机核实）

`build_notes.py` 已经有一条完整的 LLM 术语流水线：

| 位置 | 是什么 |
|---|---|
| `build_notes.py:38` | `SYS_CLASSIFY` —— 三档分类 `skip/basic/gloss`，判据**是你自己定的**：「**中英对照价值，不是"这个概念难不难"**」 |
| `build_notes.py:48` | `SYS_EXPAND_SHORT` —— 产出形如 `"marginal cost" -> "边际成本：多生产一单位产品所增加的成本"` |
| `build_notes.py:57` | `SYS_EXPAND` —— 80–160 字详解 |

**中英术语对是现成的副产品。** 缺的只是「把课件当候选词源喂进去」。

而目标格式**极简**（本机核实 `glossary/`）：**一行一个英文术语，`#` 开头是注释，无译文**。
实测规模：ECON10730=**40**、ECON10740=**36**、ECON10770=**35**、ECON10790=**28**、SOC10020=**45**。
`glossary/` 不在 git 里（`git ls-files glossary/` 为空）。

### 5.2 ⚠️ 最重要的一条：**"翻译变好了"证明不了术语表好**

**WMT25 的术语翻译赛项设了三个模式**（ACL Anthology 摘要逐字）：

> "Participants are challenged to translate texts under three modes: **no terminology,
> proper terminology, and random terminology**, allowing for a causal analysis of…"
> —— [aclanthology.org/2025.wmt-1.30](https://aclanthology.org/2025.wmt-1.30/)

**「随机术语」是拿原文里随机抽的词冒充术语。** 有这个对照，才能区分
「术语表内容确实好」和「只是提示了模型这是哪个领域」。

→ **任何 A/B 必须带随机术语对照**。这与本仓库已有的硬规矩同源
（见 auto-memory 的「相关性判据必须做零假设对照」）。

### 5.3 方法调研：别指望全自动

| 发现 | 来源 | 置信 |
|---|---|---|
| 多智能体流水线（MAPEX）才超 SOTA 无监督方法 **2.44%**（F1@5），超标准 LLM baseline **4.01%** | [arXiv 2509.18813](https://arxiv.org/abs/2509.18813) ✅已核（逐字） | 高 |
| **噪音是主要失败模式**：TermEval 2020 里 F1 最高的系统同时产出 **3435 个假阳性**（含命名实体）；D-Terminer 举例 *"BUILDING, which is part of an **all-caps title** and falsely identified as a CT"* ← **正是 PPT 标题全大写的坑** | 子代理转述会议论文，**我未逐篇回源** | 中 |
| 术语抽取的评测本身就不可靠 —— 与被测应用无关的参考表 *"is highly questionable"* | 同上 | 中 |

> ❌ **一条被剔除的引用**：子代理给了一张「ACL 2025《How Well Do Large Language Models
> Extract Keywords?》」的 P/R/F1 表（含 GPT-4o F1=0.036）。
> **我回源发现那个链接指向的是另一篇论文**（`2025.findings-acl.1131` 是讲**反讽检测**的），
> 跟关键词提取毫无关系。**那组数字一律不用。** 列在这里是为了防止它被重新捡起来。

### 5.4 设计建议（按证据强度排序）

1. **别新建提取器** —— 课件当**候选词源**接进 `build_notes.py`。
   三档判据、中文展开、缓存、prompt 都已存在且已被作者调过。
2. **做「提取 → 你勾选 → 写回」，不做全自动。** 术语表只有 28–45 条，
   **精度远比召回重要**，人工过一遍两分钟。
3. **只追加，不覆盖。** ⚠️ 术语表有两个用途，只有一个是课件能给的：
   - 领域术语（`joule` / `OLS` / `regression`）← **课件能生成**
   - **课号与教务词**（`ECON10101` / `Brightspace` / `deadline`）← **课件里没有**，
     `glossary.example.txt` 明写「**课号必须全列在这里**：同一院系的课号往往发音极近」，
     不给候选模型必然听混
4. **A/B 必须带随机术语对照**（§5.2），否则整个验证是空的。

## 6. 建议的落地顺序

| 阶段 | 做什么 | 依赖 | 成本 |
|---|---|---|---|
| **9-A** | **一条命令安装器** `install.sh`（把 §1 那 8 步收成 1 步） | 无 | 小 |
| **9-B** | **`.app` 启动器**（不含 Python；走 git/curl 分发，不签名） | 9-A | 小 |
| **9-C** | 课件 → 候选词源 → `build_notes.py` → 勾选 → 写回 `glossary/<课号>.txt` | 8-C（导入入口） | 中 |
| **9-D** | 带**随机术语对照**的 A/B，量术语表到底有没有用 | 9-C | 中 |

**顺序理由**：9-A/9-B 是**朋友能否用上**的门槛，且几乎零风险；
9-C/9-D 是**功能**，依赖上一份文档里的导入入口。
**先解决"能不能用上"，再解决"好不好用"。**

⚠️ **9-B 有一个必须先解决的问题**：`.app` 双击启动时**没有终端**，
而 `main.py:122` 每节课结束会 `input()` 问「存入 Obsidian 吗」。
它有 `EOFError` 兜底（实测 `main.py:126-128` → 默认保存，**不会挂死**），
但**用户看不到任何提示**。要么把 `--save-notes` 默认改成 `yes`，要么改成用面板问。

## 7. ⚠️ 需要**你自己**核实的一条（我不下结论）

调研 VPS 时顺手翻到：**英国大学对"学生录音 + 交给外部 AI 工具"的规定比想象严。**

曼彻斯特大学 2026-09 生效的政策里，未经授课教师书面同意，学生不得
*"Share a recording with a third party, such as external AI tools"*，
且管辖范围明确包含 *"associated materials (such as transcripts of recordings)"*。

**但这是曼大，你在 UCD。** 我搜了 UCD，**没找到直接对口的录音政策页面**
（搜到的多是 AI 教学指南、研究生用 GenAI 的原则），所以**这条我不下结论。**

**三点必须说清楚：**

1. **这不是新风险** —— ClassLive 今天**每句话的文本已经发给 DeepSeek 云端**，
   README 自己也写着「云端只在你愿意时收文本」。VPS 不改变这件事的性质。
2. **课件是另一档** —— 课件里可能含**第三方版权内容**（引用、图表、他人材料），
   比你自己听到的转录更敏感。这是 §4 里 VPS 方案的额外代价。
3. **值得花十分钟查一次 UCD 的现行规定** —— 这影响的是**你用 ClassLive 的姿势**
   （比如要不要事先跟老师打招呼），跟本次技术选型无关，但比技术选型重要。
