## 1. 项目是什么

### 1.1 一句话 + 给谁用

老师讲英文，屏幕滚出**中文双语字幕**；音频**不出本机**，课后自动整理成 Obsidian 笔记。

作者自己用（UCD 经济学本科，英文非母语，核心痛点是**跟不上语速**——
一句里两三个词没听清整句就散了），也开源给朋友用。

### 1.2 数据流

```
双击 .app
   └→ cl（bash 启动器，零参数）
        └→ ClassLive.app/Contents/MacOS/python main.py
             ├── capture.py  采音频（麦克风 / 系统声）
             ├── vad.py      断句
             ├── asr.py      转写（sherpa-onnx + Parakeet，全本地）
             ├── translator.py → cloud_translator.py（DeepSeek 云端）
             │                    └→ 断网/失败时降级到本地 Qwen3-1.7B
             └→ overlay.py   悬浮字幕窗（AppKit，磨砂面板）
课后 → obsidian_writer.py → <vault>/Lectures/ 双层笔记
```

**成本不是零**：ASR 全本地（$0），但翻译走云端。实测一节两小时课 **0.08–0.19 元**（`README.md:175`；
⚠️ README 只写了"实测 + DeepSeek 云端 + 纯转录档为 0"，**没标日期与单价口径**）。
只有三档模式里的**「纯转录」档**是零 API 请求（`README.md:418`）—— 那一档草稿、定稿、术语查询**全部**跳过模型。

### 1.3 硬约束（这些是不能碰的）

| 约束 | 为什么 |
|---|---|
| **只支持 macOS + Apple Silicon** | 本地推理依赖 MLX/Metal，悬浮窗依赖 AppKit |
| **音频不出机器** | 产品定义的第一条；只有文本上云 |
| **`capture` / `vad` 回调必须立刻返回** | 阻塞会丢音频 |
| **AppKit 调用只能在主线程** | ObjC 的硬要求 |
| **`sessions/` 只追加、禁通配符** | 曾误删过一节真实课堂记录，不可恢复 |
| **`glossary/<课号>.txt` 只追加** | 手写内容与自动内容共处一个文件（见 §3.2） |

## 3. ⭐ 本次三个变化（重点）

### 3.1 窗口：「双击 = 立刻开录」→「双击 = 课程卡片面板」

#### 变化本身

```
以前：  双击 .app ──────────────────────────────→ 立刻开麦录音
现在：  双击 .app → 课程卡片面板 → 点某张卡的「开始上课」→ 写 .course + 录音
```

**收益**：`.course`（用哪门课的术语表）从**看不见的状态文件**变成**面板上你选中的那张卡** —— 可见了。
**代价**：上课前多一步。

**双击之后实际发生了什么**（回源码核过的链路）：

```
双击 .app
 └ macOS 按 Info.plist 启动 Contents/MacOS/python（CFBundleExecutable = python）
    └ sitecustomize.py → os.execv("/bin/bash", [ …, "cl" ])
       └ cl 零参数分支（cl:204-216）→ "$PY" entry_launch.py（**独立子进程**）
          ├ 退出码 0 → 读写好的 .course → cl 继续 exec "$PY" main.py（录课）
          └ 退出码 1/2/3 → 见下表
```

⚠️ **`cl-bg.py` 不在双击链路上**（全仓只有注释引用它）—— 这条最初抄自
`entry_launch.py:17` 的注释，**那份注释自己画错了**（本次已一并订正）。

#### 面板长什么样

```
ECON10740  Exploring Economics              ← 课号 + 课名（课号不显示两遍）
7 份课件 · 73 条术语 · 上次上课 9/25         ← 从现有数据算出来，不新增存储
[ 开始上课 ]  [ 选择文件… ]                  ← 两个动作
本次加了 40 个　·　另有 20 个没加             ← 结果区**只有这一行**
```

- ⭐ **卡片本身就是拖拽目标** —— 拖到哪张卡就是哪门课，省掉「先选课再拖文件」两步。
  （HIG 的「多个可选目标时**一次只高亮一个**」是**天然满足**的 —— 代码里没有互斥实现，
  靠的是 AppKit 拖拽目标链本身一次只命中一个；⚠️ **真机上没量过**。）
- **进度**：`抽文本 3/7 → 抽候选词 1/1 → 写入 1/1 → build 1/1`
  ⚠️ 最后一段**漏了中文名** —— `prep` 发的 stage 是 `build`，而面板的 stage 表里写的是
  `notes`（**永不触发**）→ 落回显示原名。这是 `§8` 里记着的一条**未修**问题。
- ⚠️ **「跑起来之后关掉面板也继续」在双击这条路上不成立** —— prep 跑在
  `daemon=True` 线程里（`entry_panel.py:605`），面板进程一退它就跟着被杀。
  只有**菜单栏**那条（进程常驻）才真能"关掉窗口继续跑"。**方案里想要的行为，实现没达到。**
- ⚠️ **结果列表现在只有「加了」是逐条渲染的**（每条带「删」，删后出现「撤销」）；
  「没加」和「失败」**只在结果行里给计数**，没有逐条、也没有逐文件原因。
  → 这**不符合**调研提的三条硬要求（失败逐文件、原因写在那行上），是 `§8` 里**记着的未修项**。

#### ⭐ 最关键的结构决定：**独立短进程**

硬要求是「**面板崩了不能导致录不了课**」。做成独立进程之后，这条保证是**结构上**成立的，
不靠 `try/except` 兜：

```
cl 的零参数分支 → entry_launch.py（独立子进程，短命）
                    ↓ 退出码
                  cl → exec "$PY" main.py（录课那条路，一个字没动）
```

**退出码就是契约**（`cl` 只读得动这个）：

| 码 | 含义 | `cl` 怎么办 |
|---|---|---|
| 0 | 用户选了课（`.course` 已写好） | 照常录课 |
| 1 | 用户**主动关掉**面板 | **不录**（这是意图，不是故障） |
| 2 | **面板起不来** | 退回「照旧立刻开麦」 |
| 3 | 没课程可显示 | 退回「照旧立刻开麦」（别让人卡在空面板上） |

⚠️ **1 和 2 必须分开**：把「用户取消」当故障去录课 = 违背用户意图；
把「面板挂了」当取消 = 录不了课（正是要防的那件事）。

⚠️ 另有一个 `done` 闩：**决策可能在 `runEventLoop()` 之前就发生**
（那时 `stopEventLoop()` 叫得太早，之后再进循环就**永远出不来**）—— 实测挂死过。

#### 入口收敛

现在有**三条**入口（调研提醒过「只放一处会难找、放两处会混淆」）：

| 入口 | 场景 |
|---|---|
| 双击 `.app` | 开课前 |
| 菜单栏 🎧「开课前的准备…」 | **上课中**再拖课件 |
| `cl prep` | 终端 |

外加上课路径本身的退路：**`CL_NO_PANEL=1`** 退回老行为。

#### ⚠️ 未验的

- **真机上由作者完整走一遍双击 → 选课 → 录课**，这一条还没做（提交里只跑过测试闸门）。
- 面板**非 key 状态**下能收到拖拽，是用 `probe_drag.py` 手工验的（非沙盒，已验证）。

### 3.2 术语表：从「只追加」到「可删、可撤销」

#### 老纪律（还在，且是承重墙）

`glossary/<课号>.txt` 是**手写内容与自动内容共处**的文件，纪律是**只追加**：

```
prep.py 文件头（:14-22）把它写成一句话：new.startswith(old)   ← 「已有字节逐字节不变」
                                    —— 它盖住课号、教务词、首行、空行、用户手写的一切
```

⚠️ **那句是散文，不是可执行断言**（`append_terms` 里没有这行代码）。真正的强制是
**结构上的**：`append_terms` 走 `body = old` 再 `body += 新行`（`prep.py:197-204`）——
只可能往后加，不可能改前面。

**为什么不能覆盖**：`glossary.example.txt` 明写「**课号必须全列在这里** ——
同一院系的课号往往发音极近，不给模型候选，它必然听混」。
所以自动生成**只能追加**，课号那一段永远手写。

#### ⭐ 新增：真删词（作者拍板「真删，写回文件」）

删词会**打破「只追加」**，所以换成一条**更窄、但仍是可执行的**不变量：

> **除了被删的那几行，其余字节逐字不变，且顺序不变。**

实现上它不是写在注释里，而是**承重的**：

| 机制 | 做什么 |
|---|---|
| `removed_lines(old, new)` | 那条不变量的**可执行定义**（子序列判定）。**函数与测试共用同一份** —— 不在测试里另写，避免漂移 |
| 写盘前闸门 | 结果不是「纯删行」→ **`raise GlossaryError` 拒绝写入** |
| 注释行 / 空行 | **永不删** —— 它们是手写内容 |
| 匹配方式 | **按内容**，不按位置（位置会因并发而漂） |
| 撤销 `restore_lines` | **按原位置插回，不是 append** |
| 墓碑 | **不需要动** —— 这里纠正了方案里的一句话：`prepare()` 已经跳过 `appended` 里的词，删掉术语表那行不影响它，重跑不会复活。⚠️ **但有前提**：这条**只对 prep 自己加过的词**成立（它们在 `appended` 里，判定见 `prep.py` 的 `if k in have or k in tomb`）。**手写词**被删掉之后 `have` 里也没有了，**重跑仍可能被重新抽进来** —— 代码自己承认这一点 |

**「撤销不是 append」有事故依据**：NoteExpress 官方论坛的一次真实事故 ——
从回收站恢复到原文件夹，**导致原文件夹里所有题录全部消失**。
而 `glossary/<课号>.txt` 的**顺序是有意义的**（逐行喂进 prompt）。

⚠️ 实现上踩过一个坑：删掉**最后一行**时，它的原行号恰好等于还原后的 `len(lines)`，
那是**合法的插入位置** —— 当成越界会把这一行**永久丢掉**（第一次跑只插回了 1/2 条）。
现在写的是 `pos = min(idx, len(lines))`。

#### 配套：反幻觉复核（第一批就有）

LLM 抽出的候选**必须在语料里真的出现过**，否则不自动加入。
依据是自家引的 EDM 2026：喂长上下文会让 WER 从 32.3 **涨到** 43.4。
有了这道复核，`confidence` 就从「承重墙」降级成「排序偏好」——代价只有一次字符串匹配。

#### ✅ 已修（2026-09-27，提交 `d935d5a`）

**`remove_terms` / `restore_lines` 现在与 `prep.prepare` 拿同一把本课锁。**
`prep.state_lock_path()` 是锁路径的**唯一定义点**，面板的 `lock_of()` 与 `prepare()`
的 `state_path` 同源（都走 `paths.prep_state(course, root=state_root)`）。
拿不到锁就**抛 `GlossaryError`**，不静默返回「没删到」—— 后者会让面板把
「正在并发」说成「这个词不在表里」，跟用户说错原因。

（写这篇时这里是「已知未修」。当前剩余项的唯一定义点是
`docs/REVIEW-midpoint-20260927.md` §9。）

### 3.3 点击才开始录音

#### 变化

见 §3.1 的图。核心是**多了一次显式确认**：用户点「开始上课」才写 `.course` 并开录。

**为什么这不是"多此一举"**：它同时解决了三个问题 ——

1. `.course`（这门课用哪份术语表）从隐式状态变成**可见选择**
2. 上课前有地方**看准备度**（几份课件、几条术语、上次什么时候上的）
3. 有地方**拖课件 / 删词**，而不用打断上课

#### 实现上的三个要点

| 要点 | 内容 |
|---|---|
| **独立进程** | 见 §3.1。面板崩了最坏是本进程非零退出，`cl` 照旧走老路 |
| **写 `.course` 用 `pathlib`** | 不用 shell 重定向 —— 课号来自界面，不该有任何机会被当成 shell 语法 |
| **`done` 闩** | 决策可能发生在事件循环之前；早停循环会让进程**挂死**（实测） |

#### 退路

`CL_NO_PANEL=1` → 零参数分支直接跳过面板，回到「立刻录课」的老行为。

## 6. 已尝试过的方法（含**走不通**的）

### 6.1 走不通的（别再试）

| 方法 | 为什么不行 |
|---|---|
| **合成拖拽**（`CGEventPost` 模拟 Finder 拖放） | 能移动光标，**起不了真拖拽会话** —— `NSDragPboard.types()` 空、`changeCount == 0`。两次「拖拽不行」的结论由此而来，**都作废** |
| **ASR 热词偏置**（把术语表喂给 ASR 影响识别） | 实测**没有可用区间**：权重 2.0 不触发 / 8.0 输出崩坏 / 20.0 直接背热词表。机理：声学证据不支持那个词时，掰回来的偏置会大到压过声学。→ 改喂**翻译 prompt** |
| **Docling**（重依赖的文档抽取） | 作者 brief 明确「不需要那套重的」。改用 **PDFKit + stdlib `zipfile`**（PPTX）+ Vision 兜底 —— **新增依赖 = 0** |
| **PyInstaller 自包含打包** | Finder 下 PATH 被砍、C 扩展隐式 import 静默失败（sherpa-onnx 正是）、6.0 起符号链接问题 |
| **发 DMG** | 浏览器下载会打 `quarantine` → Gatekeeper 拦。走 git/curl 完全不用签名（实测） |
| **VPS 参与** | 同类的自建服务器清一色是**同步**不是算力；那点活不值得引入合规面 |
| **WeasyPrint**（PDF 引擎） | 本身能用（见 §5 ③），但会把 **Homebrew 变成新依赖**；本项目只支持 macOS，「跨平台」价值为零 → 选 **WebKit**（`WKWebView.createPDF`）。⚠️ 选它的理由**不是速度** —— 那条速度对比是错的，见 §5 ③ |

### 6.2 用上了、而且**以后也要用**的方法

| 方法 | 为什么有效 |
|---|---|
| ⭐ **变异测试** | **唯一**能抓「假测试」的招（改一处实现，看断言会不会红）。本轮写错了一批假测试（当轮逐条核过；⚠️ **没留清单，这个条数不可独立复核**） |
| ⚠️ **跑变异前必须 `rm __pycache__/*.pyc`** | 同尺寸变异的 mtime 会和 `cp` 还原撞在同一秒 → CPython 判定缓存有效 → **`cmp` 说源码逐字还原，跑的却是变异版**（被骗过三轮） |
| **隔离跑器**（`state_root=ISO`） | 验写端不碰真数据。⚠️ **但它会整个绕过生产路径** —— 面板那个 `AttributeError` 只在 `state_root=None` 时触发，隔离跑器从没跑到过 → **两种都得跑** |
| **判据要在"事情发生的那一刻"成立** | 「真 glossary 未变」原本只在末尾判，而那时撤销已经把文件放回去了 → 变异把删除打向真文件时它**报绿** |
| **手拖验收探针**（`probe_drag.py`） | 合成拖拽不行之后的替代方案；作者手拖一次即可 |
| **同进程跟冻住的老配方对拍** | 面板判据不绑机器、不靠手挑（`test_panel.py`） |

### 6.3 AppKit 的三个坑（本轮踩过，会重复踩）

| 坑 | 表现 | 正解 |
|---|---|---|
| ⭐ **`objc_own` 按 key 缓存类** | 回调写进 `own()` 的 namespace → 第二次调用拿回**同一个类** → **点哪张卡都触发第一张的动作**（本轮踩两次：按钮、落点） | **回调挂实例**：把函数存成实例属性、再 `getattr` 读回来（属性名各模块不同 —— `panel.py` 用 `_cb`，`entry_panel.py` 用 `_fn`） |
| **`setTarget_` / `setDelegate_` 是弱引用** | target 是局部变量 → 被 GC → 「**点了没反应，还不报错**」 | 调用方**必须留住 target** |
| **`NSCell` 模态跟踪循环** | 在按钮 action 里拆掉**发送者自己的视图树** → 主线程被卡 → 所有按钮失灵 | 用 `AppHelper.callAfter` **把重建推迟出 action** |
