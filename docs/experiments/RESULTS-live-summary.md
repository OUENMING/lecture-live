## 社区调研（决定 A3 那条路线的依据）

| 来源 | 说什么 |
|---|---|
| `arxiv 2512.17083` §9.1「Boundary Selection as a Separate Step」 | 逐字：「**separating scoring from selection enables boundary density to be controlled independently of scoring granularity**」 |
| `arxiv 2601.03276` Appendix A | 逐字：「Segments that are **too short are concatenated with a neighbouring segment** and segments that are **too long are recursively segmented**」；其 prompt **一个字都不提长度或数量** |
| `arxiv 2512.17083` | 控制粒度的标准旋钮是**阈值 τ + 最小间距 g**，不是「目标段数」 |
| PELT（变点检测） | 「**Minimum segment length** … raising it **suppresses short, noise-driven segments**」 |
| YouTube 官方章节规则 | 只有「≥3 章 · 每章最短 10 秒」，**从不发布目标章数** |
| TextTiling / C99 | 经典算法用**停止条件**，不用粒度指令 |

⚠️ **没找到**任何一手来源推荐「在 prompt 里给模型一个章数/时长目标数字」。
⚠️ **没找到**「一节讲座该切几章」的公开规格。

→ 据此加的常量：`MIN_CHAPTER_S = 180` · `MAX_CHAPTER_S = 600`
（两个都要：只加 MIN → 模型保守时整节课只有一章；只加 MAX → 模型换得勤时照样碎）

## ⚠️ 阶段 2 结束时的账

### 一、课务假阳性：**收窄了，但没收干净**

32 → 11 条（见上面的三轮对比）。剩下 11 条 vs 人判 ~7 条。
⚠️ **讨论型那节仍然偏松**（5 条 vs 人判 ~2 条）。
形态没变：**学生自我介绍**、**教师联系方式**、"一张纸在传，只写学号"、
"下面两张幻灯片讲政府债务" 这类描述**当下动作**的句子。
⚠️ **学生视角的评审原话**：「假阳性高到会让我**以后都不看它**」——
那才是真损失（真 deadline 出现时也不看了）。

### 二、⭐ 切点仍然是**时间驱动**，不是**话题驱动**（**没解决**）

```
理工    4 章 · [617, 618, 619, 662]s     → 4/4 全是 MAX 切的
讨论型  5 章 · [462, 528, 611, 641, 642]s → 3/5
经济    5 章 · [428, 605, 614, 627, 668]s → 4/5
合计    14 章里 11 章 ≥ 600s（= `MAX_CHAPTER_S`）
```

**推理**：`MIN_CHAPTER_S = 180` 拒掉太短的，`MAX_CHAPTER_S = 600` 强制切开。
所以一章的时长**只可能**三种来源 ——
`≥600` 一定是 MAX 切的 · `180 < d < 600` 才是话题切的（或整节下课）· `<180` 不可能存在。
→ **11/14 是 MAX 切的。**

**已经修过的**：`_topic_prev()` 原来返回**当前章的标题**（被喂回 prompt 当「上一段的主题」
→ 模型一开章就倾向沿用 → 边界全被抑制）。A4 起改回**上一窗的主题**，
对齐原 `main.py` 里 `atom_st["prev"]` 的行为。

⚠️ **但修完这个指标没动**（A4 理工 3/5、A5 理工 4/4 仍是 MAX 切的）——
**抑制源拿掉了一个，模型自己提的边界还是不够多。**
→ 这条**还开着**，需要新的一轮（候选方向：降 `MAX_CHAPTER_S` 让 MAX 切得更碎再看模型会不会补边界；
或把边界判断也交给一个独立的打分步骤，同 `arxiv 2512.17083` §9.1 那条）。

**后果**：切点**碰巧**离真实边界不远（拿 A0 的 14 个自然边界对过，差约 2 分钟），
但**它是巧合还是规律，这三节还答不了**。

### ⚠️⚠️ 这个数有三条**不能忽略**的边界

**① 「原子漏了」那个说法没有证据支持（对照把它否掉了）**

讨论型 (a′)=83.3% 看着像「原子漏了 2 条」。查了：
**两条都落在有 5 条原子的窗口里**（不是空窗），但那个窗口**顶到了原子的 5 条上限**。
→ 假设「是 5 条上限挤掉的」。**做了对照**：命中/漏掉的句子落进「顶格窗」的比例
（理工 5/12 vs 顶格窗占比 33% · 经济 9/12 vs 69%）**与基线一致** →
**上限不是原因**。漏掉就是模型给那条原子挑了别的 `src`。

**② ⚠️ Jev 的 top-12 本身不可复现**（同输入连跑三次）

```
第 1 次  [198, 219, 264, 265, 321, 341, 353, 405, 442, 465, 528, 566]   (a′) 11/12
第 2 次  [198, 219, 321, 341, 353, 405, 442, 447, 465, 498, 528, 566]   (a′) 10/12
第 3 次  同第 2 次
→ 稳定 10/12 条，三次**一共出现过 14 条**不同的句子
```

⚠️ **精确口径**：Jev 的**概率值**是稳的（早先实测中位差 0.000、0.15 处吻合 98%），
但**卡在第 12 名附近的那几条会换人** —— 98% × 541 句 ≈ 11 句可能翻，
所以 top-12 里翻 1–4 条是**预期之内**的。
→ 上表 (a′) 那几个数应当读成**带 ±1–2 条的带**，不是精确值。

**③ 这个数不能直接读成「合成层漏了一半重点」**

- **问题不同**：Jev 问「这句是不是全节重点」，而 2–4 句的章节摘要要写**骨架**，
  不是把概率最高的几句抄下来。两者的正确答案本来就不该重合。
- **结构上限**：三节合成句一共 15/19/20 条，还要覆盖本章的非重点内容。

⭐ **但 (a′)=94.4% 是硬结论**：原子层基本没漏（漏的 2 条也不在顶格窗上）。
**漏点主要在合成那一步** —— 计划原话，这正是「**读完能不能懂**」最该暴露的失败形态。

⭐ **讨论型 vs 理工是个信号**：(b) 75.0% vs 41.7%。讨论型是**离散观点多**的课，
理工是**满黑板推导**的课 —— 与计划 §7.3 那句「经济课只能部分代替理工课」一致，
但**方向是反的**：**推导型的内容更难被压成几句摘要**。
（⚠️ 只有 1 节理工样本，且是**作者没上过的**朋友的课 —— 别当结论。）

## ⭐ 断网 / 积压 / 重试（`--fail-window`）

**2026-09-30 第一次真跑。** 跑之前先修了一个**从加进来那天起就没跑成过**的东西：

> ⚠️ `_secs()` 只吃 `"HH:MM:SS"`，而 `--fail-window` 的格式是 **`HH:MM`**
> （argparse 的 help 和计划 D10 的例子都是这个形状）→ 一解析就 `ValueError`。
> **这个参数从来没成功启动过**，而文档里一直写着"参数实现了，没实测过"。
> （`--dry` 那时也**不认** `--fail-window` —— 所以连免费验一遍的路都没有。已补。）

**实验设计**：理工那节，`--fail-window 14:12-14:42`（30 分钟停机），之后 8 分钟恢复期。

| 指标 | 值 | 说明 |
|---|---|---|
| `backlog_peak` | **20** | 正好顶到 `MAX_PENDING = 20` |
| `gaps` | **3** | 全是 `state="dropped"`（超出积压上限被丢的） |
| `retries` | **75** | 停机期间的重试尝试（`RETRY_S = 30` → 1800s ÷ 30 ≈ 60，加上恢复期的） |
| `windows` | **30** | 33（无断网时的窗口数）− **3**（丢掉的）= 30 ✅ 数自洽 |
| `atom_calls` | **30** | ⭐ **= 窗口数** → 没丢的那 20 个积压窗口**全恢复了** |
| `elapsed_s` | 50.0 | 含恢复时一次性消化 20 个窗口的突发 |

**成本**：32 次 DeepSeek 调用（失败的不花钱 —— 桩在发请求**之前**就抛）。

⭐ **重试这条路是通的**：`atom_calls == windows`，积压全部追上来了。

### ⚠️⚠️ 但它挖出一个真缺陷：**恢复那一刻，积压的那批会全塌成一章**

```
章节（有断网）  id=0 内容 14:08:06-14:11:47  句 1-39
                id=1 内容 14:15:56-14:50:22  句 87-482     ← 一章盖了 34.4 分钟
对照（无断网）  4 章 · 每章约 10 分钟
```

⚠️ **句 40–86 不属于任何章**（那是被丢的 3 个窗口）—— 这个**是设计如此**（`gap` 记录会渲染成空缺）。

**但第二章跨 34.4 分钟**，而 `MAX_CHAPTER_S = 600`（10 分钟）本该强制切 3 次。为什么没有：

**决定性实验**（同一份代码，只改一个自变量）：

```
对照组：窗口之间 now 正常推进 200s，5 个**不同主题**的窗口  → 4 章
实验组：窗口之间 now **一动不动**（= 积压恢复那一刻）      → **0 章**
```

**机制**：`_absorb` 里 `t_open = now`（**消化那一刻的模拟钟**，见 `live_summary.py` 那行注释 ——
它当初是为了修「两个时钟域混用导致判据恒不成立」）。而一次 `step()` 里所有窗口
**共享同一个 `now`**，于是：

```
`now − t_open` ≡ 0  <  MIN_CHAPTER_S = 180  →  每一个主题切换都被并回当前章
```

→ **断网 25 分钟再恢复，那 25 分钟的内容（含其中十几次换题）会塌成单独一章。**

**这个缺陷是「失败不丢窗口、留着重试」这个新功能带来的副作用** ——
而它**只有跑 `--fail-window` 才看得见**（不跑的话，这功能看起来完美：调用数对得上、
一条没丢、还有 `gap` 记录）。**这就是「参数实现了但没跑过」的代价。**

✅ **已修**（2026-09-30）。修法**不是**去动 `MIN/MAX` 的时间域（那会让判据夹具的
时间模型和实现分叉，连带改一串既有判据）—— 而是**给积压里的每个窗口算一个
「本该在什么时刻被消化」的有效时钟**（`_process_pending` 里，把**内容时间差**搬到
`now` 这根轴上，锚在最新那一窗）：

```python
newest_c = self._pend[-1][-1][1]              # 最新那窗的内容时刻 = 「现在」
now_eff  = now - _span_s(buf[-1][1], newest_c)  # 越旧的窗口，有效时刻越早
self._absorb_window(buf, obj, now_eff)
```

⭐ 语义上本来就该如此：一个来自 14:16 的窗口，就该**当作 14:16 处理**。
⭐ **单一时钟域这个不变量保住了**（`t_open` 仍然是 `now` 域的）。
⭐ **只有一个窗口时 `now_eff == now`** —— 正常上课走的那一支**逐字不变**。

**修完实测**（同一份真数据、同一条 `--fail-window 14:12-14:42`）：

| | 章数 | 每章内容跨度 |
|---|---|---|
| 修前 | **1 章** | **2075s（34.6 分钟）** |
| 修后 | **4 章** | 617 / 618 / 617 / 662s |

⭐⭐ **而且修后的章节边界 `1-115 / 116-227 / 228-347 / 348-482`
与「完全没断网」那一轮（A5）逐字相同** —— 断网不再扭曲章节结构了。

⚠️ **判据的上界是 `MAX + 一窗`，不是 `MAX`**：强制切发生在**下一个窗口边界**，
必然过冲一个窗口（真数据 662s vs 上界 677s）。⚠️ 写成严格 `<= MAX` 会把
**正确行为**判成失败 —— 我没量过的东西不许当判据。

作者 2026-09-30 拍板「修」。最后选的**不是**那三个里的任何一个，
