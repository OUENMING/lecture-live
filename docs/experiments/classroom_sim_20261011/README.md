# 实验：模拟真实课堂（大阶梯教室 / 小班·workshop）的噪声与远场，再拿它测 ClassLive

> 2026-10-11 · 起因：ClassLive 的既有语料只有两种极端 —— `econ_*.wav` 是 TTS 合成（干净、匀速，
> WER 只能当乐观上界），`ocw-14.01-lec11` 是**安静**的 OCW 课堂录音（源信噪比 44.8 dB，口径见 §2.2）。
> 而产品真正要活的场景是：**阶梯教室后排、有人咳嗽、有人翻书包、椅子在响**。
> 这份实验补的就是中间那一大段。

## 0. 一句话

用**真课录音**当语音、**实测/仿真 RIR** 当房间、**真实录音的人群噪声 + 事件音效**当干扰，
按目标 SNR 混出「2 个场景 × 3 个座位 × 4 个噪声档」共 24 份 + 2 份对照，每份 5 分钟，
再喂进**生产那两层**（`draft_engine` 草稿 = Nemotron 流式 · 定稿 = 云端 Worker→Groq 或本地兜底）
量 WER / 漏段 / 回改率 / 延迟。

## 2. 怎么造：三条正交的轴

三个轴分别动，一次只动一个，才知道是谁造成的（CHiME-3 之后的标准抱怨就是"真实数据没有单一可控的
难度轴"，所以这里**把轴拆开、每条都实测标出来**）。全部实测值在 `manifest.json` 里，下表是它的摘要。

| 轴 | 取值 | 怎么实现 | 依据 |
|---|---|---|---|
| **场景** `scene` | `hall` / `seminar` | 用 **AIR 数据库的实测 RIR**（随 SLR28 一起分发）：`lecture` 房间（RT60 实测 0.84–0.87 s）对"阶梯教室"，`meeting` 房间（0.32 s）对"小班/研讨室"；底噪素材也换 | 演讲厅常见 RT60 0.7–1.0 s；小教室上限 0.6 s（ANSI/ASA S12.60 对核心教学空间的规定；未处理的老教室实测 0.8–1.4 s） |
| **座位** `position` | `front` / `mid` / `back` | 同一房间内**三条真实测距下录的 RIR**；直混比取 RIR 实测；再叠**自由场距离衰减** −20·log10(d/d_front)（封顶 −18 dB） | 教师语音在 1 m 处 60–65 dB SPL，**距离每翻一倍掉 6 dB**；DRR 随距离单调下降 |
| **噪声档** `level` | `quiet` / `snr20` / `snr10` / `snr0` | 整条噪声（底噪 + 事件）按目标 SNR 缩放，标称值按**前排未衰减**的语音活跃功率定标 | CHiME-1 用 9…−6 dB；MUSAN 那套常用 {0,5,10,15} dB；Whisper-AT 把 20 dB 当"干净"、−10 dB 当"被污染"；课堂实测 SNR 常在 **−7…+5 dB** |

按目录名盲挑就会挑到它。）

### 2.2 两条口径（都踩过坑，写清楚免得数字没法比）

**SNR 的定义点（只此一处）**：`P_语音 = 语音活跃帧上的功率`（拿干净源的掩码去框处理后的语音），
`P_噪声 = 整条噪声信号的平均功率`。manifest 里有两个数：
- `snr_added_db` —— **加进来的那条噪声**相对语音的 SNR（标定值的实测）；
- `snr_total_db` —— 把**源自己的底噪**也算进去的有效总 SNR。因为叠进去的混响尾巴会填满停顿，
  它比 `snr_added_db` **低**（hall 前排标称 20 dB → 有效 20.4 dB；后排标称 0 dB → 有效 −0.06 dB）。
  报数时说清用哪个。
- 另外记一个 `snr_est_db`（分位数门限的估计）：它在噪声大时会把噪声帧也算成语音帧，**越吵越乐观**，
  实测标 0 dB 的那份它估 17 dB —— 只当旁证，不当口径。

**短时事件按「相对底噪 RMS 的峰值」定标**（+12…−2 dB），不按 RMS：一声椅子响的 RMS 会被它前后的
安静摊平，按 RMS 定标会定得过响（踩过：按 RMS +16 dB 时实测事件峰值冲到语音之上 +23 dB，等于在
教室里放炮）。事件用**泊松间隔**排（均值 22 s，5 分钟约 12–17 次），**不走**房间尾巴（近处的一声
椅子响不是扩散场），底噪走。

## 3. 语料长什么样

`~/.classlive/eval/classroom_sim/mix/` —— **26 份 16 kHz 单声道 wav，每份 5 分钟，共 241 MB**：

| 组 | 份数 | 说明 |
|---|---|---|
| `{hall,seminar}_{front,mid,back}_{quiet,snr20,snr10,snr0}.wav` | 24 | 主grid：2 场景 × 3 座位 × 4 噪声档 |
| `{hall,seminar}_src_raw.wav` | 2 | **对照件**：源素材原样（不加房间、不加噪声、不衰减） |
| `ref/hall.txt`、`ref/seminar.txt` | — | 人工字幕切出的参考文本（677 / 762 词），WER 的分母 |
| `ref/control_ocw_lec11_600s.txt` | — | **外部对照**用的参考：既有的安静 OCW 语料（`14.01 lec11` 的 600–900 s，795 词）。拿它跑同一个量具，就知道"这些 WER 里有多少是流水线本身的账、多少是噪声的账" |
| `manifest.json` | — | 每条：RIR 与实测 RT60/DRR/距离、标称与**实测** SNR、事件清单（时刻 + 音效名 + 电平）、sha256 |

实测 SNR 的覆盖范围：**+20.4 dB（hall 前排、20 dB 档）… −3.4 dB（seminar 后排、0 dB 档）**，
两端都比真实课堂（−7…+5 dB）更宽一点，够把曲线两端都压出来。

⚠️ **两个场景不能直接横比**：源素材**自己**的信噪比差着 20 dB（18.06 是 34.6 dB，
BMM 只有 13.0 dB —— 后者的底噪是低频轰鸣，0–500 Hz 占七成能量）。所以 `seminar` 每一档都比
`hall` 差，那是素材的账，不是噪声档的账。同场景内跨座位/跨档位比才是干净的。

## 4. 参考做法：别人是怎么做这件事的

先查后做，免得自创一套没法跟别人的数字对齐的口径。

| 出处 | 做法 | 我们跟/不跟 |
|---|---|---|
| CHiME-1 | 真实客厅录音，SNR 9…−6 dB（自然起伏，不是人工缩放的） | 档位范围照抄 |
| CHiME-3/4 | 「真实数据 + 仿真数据」两条腿：干净语音 × 实测 IR + 真实录的噪声 | 跟（本实验走的就是这条） |
| CHiME-7/8 | 噪声从真录里抠、干净语音用 LibriSpeech、RIR 用实测（VoiceHome）、**逐说话人 SNR 对齐真实数据**（用 Brouhaha 估） | 思路跟；"对齐真实数据"这一步我们做不到（没有目标域录音），所以改成按文献里的课堂 SNR 区间定档 |
| REVERB Challenge | 仿真（WSJ × 实测 RIR + 真实噪声）+ 真实两条腿 | 同上 |
| MUSAN / TheWhisper 等 | babble 噪声在 {0,5,10,15} dB 上调 WER 曲线 | 档位照抄 |
| NVIDIA Riva noise-augmentation 教程 | `snr_mixer()`：把干净语音与噪声各自归一到 −25 dBFS，再按 SNR 缩放相加 | 和我们的 SNR 定义一致（活跃语音 vs 噪声功率） |
| Interspeech 2017 房间仿真器（Kim et al.） | SNR 在 0–30 dB（均值 12），**SNR 分布以"目标到麦的距离"为条件**；T60 随机 0–900 ms | ⭐ 座位轴与噪声档**不是独立的**这件事，就是他们的结论；我们照做（后排除非噪声也小，否则 SNR 必然低） |
| Whisper-AT | 把 20 dB 当"干净"、−10 dB 当"被噪声污染" | 档位上下界照抄 |
| Speech Robust Bench (SRB) | 114 种扰动，系统扫稳健性 | 只借"多轴、逐轴报数"的形式 |
| AssemblyAI（2026 实测） | 4 个 ASR 系统 × 9 种噪声 × 500 段医学语音：**降噪之后错误率反而更高**（40 个配置全部如此，1.1%–46.6% 绝对上升） | 记下来：本仓库的 `denoise_ab.py` 若要做，先看这条 |
| 教室声学文献 | 课堂实测 SNR 常见 **−7…+5 dB**；儿童 babble 是最难的噪声之一；Whisper 在高 babble 下会**整段幻觉**（"the the the…" 复读 206 次） | 解释了为什么"事件 + 人群"要一起上；幻觉这条我们在指标里也要看（漏段/插入） |

### 5.3 ⚠️ 这一轮的引擎口径（先读这段再看数字）

这一轮**只对齐了"分段"这一层**，识别那两层用的是兜底件，**不是生产配置**：

| 层 | 这一轮用的 | 生产实际是 | 影响 |
|---|---|---|---|
| 分段 / VAD | `stream_eval.replay` 内复用生产的 `Segmenter` + `PeakNormalizer` + `vad.find_valley_cut` | 同左 | ✅ **一致**，"漏段"这类结论算数 |
| 草稿 | **Parakeet**（每秒重转最近 10 s） | **Nemotron 流式**（`draft_engine.py`，R3 P1 已落地） | ❌ 回改率 / 首字延迟要重测（回改率差 50 倍） |
| 定稿 | **本地 Parakeet**（`--final parakeet`） | **云端**（`cloud-asr.json` 开着，Groq/千问优先） | ❌ WER 绝对值要重测（仓库自己的对照：同语料 Groq 10.4% / 漏 0.7% vs 本地 12.0% / 2.5%） |

所以 §5.1、§5.2 里 **WER 的绝对值偏高**、**回改率不是生产数字**；
"哪一档更差"的**排序**大概率仍成立（噪声是加在输入上的），但这一条**要重测才算数**。
**站得住的**：漏段（分段层）、以及"0 dB 档崩在分段而不是识别"这个判断 ——
而且正因为定稿在云端，这一条更要紧：**VAD 判不出语音，云端再准也拿不到东西**。

### 5.5 ⭐ 标定：你的**真实课堂**落在模拟的哪一档

光有模拟数字没有参考价值 —— 得知道"我造的这一档，像不像你真正在上课的那间屋子"。
拿 Owen **自己那节真课**（2026-10-09 12:07 ECON10770，43.2 分钟，笔记本麦在现场录的）来标定。

两个**互相独立**的口径，都算在同一批文件上：

| 口径 | 真课 10-09 | `hall_back_snr10` | `hall_back_snr20` | `hall_back_quiet` |
|---|---|---|---|---|
| 掩码口径（语音活跃帧功率 ÷ 非活跃帧功率） | **9.25 dB** | **9.57 dB** | 16.96 dB | 19.95 dB |
| 分位口径（`active_level_db`，manifest 的 `snr_est_db`） | **18.42 dB** | **17.70 dB** | 22.30 dB | 42.40 dB |

两个口径各自差 4–8 dB（定义不同），但**都把真课落在 `hall_back_snr10` 上**，误差 < 1 dB。
结论：**你那节课的声学难度 ≈ 模拟里的「阶梯教室后排 + 10 dB 档」** ——
而那一档在本地定稿下是 **WER 43.6% / 漏段 19.2%**（旧引擎；云端那一档待测，见 §5.6）。

三条限定，免得读过头：
1. 真课是**笔记本麦近场**（离讲师 0.5–1 m），模拟的 `back` 是 **10 m 远场** ——
   这是**噪声水平**上的对应，不是几何上的对应。但决定 ASR 难度的正是有效信噪比，所以这个对应有效。
2. 真课只有**过了 `PeakNormalizer` 之后**的那份录音（滑动峰值会在安静处把增益拉上去、
   把底噪一起放大：同一份过完归一化，真课从 9.25 掉到 6.94 dB）。所以严格说两边还差一层。
   好在归一化对两边的**方向相同**（都降 SNR），落点判断不受影响。
3. 真课的"非活跃帧"里含**没人讲话**的时间段（活跃帧只占 25–35%），
   模拟里的非活跃帧则全是人群噪声。所以这是个**量级锚点**，不是精密标定。

**这条标定的用处**：证明模拟的噪声档**不是在夸张**。真课正好落在我扫的
`snr20 / snr10 / snr0` 三档的**中间那一档**上 —— 也就是说 `snr0` 那一档不是"不可能发生的极端"，
它离你只差一档。

### 5.9 这一轮读出来的东西

1. **安静档几乎免费。** 同语料内 `src_raw` → `back_quiet`：11.4% → 13.2%（+1.8 pp）。
   也就是说"换个房间 + 坐到后排"本身只值 2 个百分点 —— 真正吃人的是**噪声**。
2. **断崖在 10 dB 和 0 dB 之间，而且座位把它往前推。** hall 前排 10 dB 档还有 15.7%，
   后排 10 dB 档已经 **43.6%（漏 19.2%）**——"后排 + 教室里有点吵"就已经不能用了。
   参照文献：课堂实测 SNR 常在 −7…+5 dB —— **真实教室落在这个断崖里，不是在它右边**。
3. **崩的方式是"漏"，不是"认错"。** 0 dB 档 WER 67–99%，其中**漏段 45–95%**：
   VAD 先把语音判成噪声，ASR 根本没机会认错。要救这一档，得在**分段/VAD**上想办法
   （增益、降噪只喂 VAD、双阈值），而不是换更准的 ASR。
4. ~~**草稿回改率同步爆炸**：安静档 9–19% → 0 dB 档 39–51%，实时字幕会疯狂跳字。~~
   ⚠️ **这条作废（2026-10-11 晚）**：那个数是**旧草稿路径**（Parakeet 每秒重转最近 10 s）的
   行为。生产在 R3 P1 之后草稿走 **Nemotron 流式**，同一节课实测回改率 **0.69% vs Parakeet 36.6%**
   （`PLAN-streaming-asr.md` §0.1）。拿 Parakeet 的数说流式的体验是错的。要重测 —— 见 §5.4。
5. ⚠️ **首字延迟在噪声下会假装变好**（1.0 s → 0.47 s）：不是变快了，是 VAD 判出来的段
   变少、变短了。**延迟指标必须和"漏段"一起读**，单看会得出反向结论。
   （延迟的**绝对值**同样受草稿引擎影响，见 §5.4。）
6. **跨语料的绝对 WER 不可比。** 既有那节安静真课是 15.8%，比我们"安静档"的 11–13% **还高**——
   差的是**内容与字幕风格**（那节是经济课、术语与数字多），不是加料。所以第 5.2 节那张表
   只用来回答"量级对不对"，**不要**拿它算"加料贵了多少"；那个只能在同一份语料内看（第 5.1 节）。
7. 一条**线索**（不是结论）：同样 10 dB 档，hall 后排 43.6% vs seminar 后排 24.7%，
   而两者房间的 DRR 差着 14.5 dB。像是"混响比人多更致命"，但两边的**素材内容也不同**，
   要坐实得拿同一段语音过两个房间 —— 那是下一轮的事。

## 6. 这套模拟**测不出**什么（别过度解读）

1. **不是"从零模拟"**：源素材**已经是真课录音**（自带那个房间的混响、自带当时的麦克风）。
   我们加的是**再叠一层**传播与噪声。所以：
   - 绝对 RT60 / DRR 读数是"相对源录音"的，不是房间的真实值；
   - `front` 不等于"坐在前排"——它等于"源录音本来的样子"。
   **座位轴是相对劣化轴，不是绝对位置轴。**
2. **没有真实观众**：噪声是素材拼的，事件时刻是随机的，没有"观众真的在笑"那种与内容相关的反应。
3. **单声道、16 kHz**：生产管线就是 16 kHz 单声道，所以这里对齐；但真实教室是空间化的。
4. **不含翻译层**：这里量的是 ASR 那一层。译文质量对噪声不敏感（除非 ASR 先错），要量翻译得另外做。
5. **没有目标域真值**：WER 的分母是 OCW 的**人工字幕**，而人工字幕本身会省略口误/重复
   （"嗯""这个"这类），所以对所有条件都有一个**共同的高估**；**只有相对比较有意义**。
